# 이 레포에서 문서를 쓸 때

`ideation` 은 코드가 없는 문서 저장소입니다. 소다쿠키 팀이 키로톤 본선(9/20)에 쓸 아이디어 후보를 쌓아두는 곳입니다. 여기서 하는 작업은 대부분 마크다운 문서를 추가하거나 고치는 일입니다.

전체 규칙은 [CONVENTIONS.md](../../CONVENTIONS.md) 와 [CONTRIBUTING.md](../../CONTRIBUTING.md) 에 있습니다. 아래는 문서를 만들 때 반드시 지킬 것만 뽑은 것입니다.

## 파일 위치와 이름

- 아이디어 문서는 `ideas/YYYY-MM-DD-제목.md`
- 조사 자료는 `research/주제.md` (날짜 없음)
- 이미지는 `assets/문서파일명-01.png`
- 루트에는 운영 문서(README, CONTRIBUTING, CONVENTIONS) 외에 새 파일을 만들지 않습니다.
- 파일명은 소문자와 하이픈만 씁니다. 공백과 밑줄은 쓰지 않습니다.
- 새 폴더를 만들기 전에 사용자에게 먼저 확인합니다.

## 아이디어 문서 형식

`ideas/TEMPLATE.md` 의 앞머리와 섹션 순서를 그대로 씁니다.

```yaml
---
title: 문서 h1 과 동일
status: raw | exploring | shortlist | parked | dropped
owner: GitHub 아이디
created: YYYY-MM-DD
tags: []
---
```

섹션 순서는 한 줄 요약 → 문제 → 해결 방식 → 핵심 기능 → 만들 수 있을까 → 참고. 이 순서가 판단 순서이므로 바꾸지 않습니다.

내용을 모르는 섹션은 그럴듯하게 채우지 말고 비워둡니다. 빈 섹션이 아직 안 풀린 지점을 드러내는 신호입니다.

## 쓰는 방식

- 한국어로 씁니다. 기술 용어는 원어 그대로 씁니다.
- 결론을 먼저 씁니다. 배경 설명부터 시작하지 않습니다.
- 확인한 것과 추측을 구분합니다. 검증하지 않은 내용은 "확인 못 함" 이라고 표시합니다. 특히 API 요금, 응답 속도, 무료 한도처럼 사실 확인이 필요한 항목을 단정하지 않습니다.
- 한 문장은 한 줄에 씁니다. 보기 좋게 하려고 문장 중간에서 줄바꿈하지 않습니다.
- 이모지는 쓰지 않습니다.
- h1 은 문서당 하나입니다. 제목 계층을 건너뛰지 않습니다.
- 링크는 상대경로, 코드블록에는 언어 표시, 이미지에는 대체 텍스트를 넣습니다.

## 접은 아이디어

문서를 삭제하지 않습니다. `status` 를 `dropped` 로 바꾸고 왜 접었는지 한 줄 남깁니다.

## 커밋과 브랜치

`main` 에 직접 커밋하지 않습니다. 브랜치는 `idea/`, `research/`, `docs/`, `chore/` 중 하나로 시작합니다.

커밋 메시지는 `타입: 내용` 형식이고 타입은 브랜치 접두어와 같습니다. 한국어로, 50자 안쪽, 마침표 없이 씁니다.

```
idea: 강의자료 요약 도우미 추가
research: Whisper API 요금·지연 조사
docs: 아이디어 선별 기준 보완
```

커밋 하나에 문서 하나가 기본입니다. 여러 아이디어를 한 커밋에 몰지 않습니다.

## 아이디어를 평가해 달라고 할 때

하루 안에 데모가 나오는지, 발표에서 시연할 장면이 그려지는지를 같이 짚어줍니다. 이 두 가지가 본선에서 후보를 자르는 기준입니다. 다만 최종 판단은 사용자가 하도록 남겨둡니다.
