# 근처에 온 김에 에이전트

## 한 줄 요약
반품, 세탁물 수령, 장보기처럼 장소가 있는 할 일을 자주 미루는 사용자가 생활 심부름을 등록하면, AI가 시뮬레이션된 현재 위치에서 처리할 일을 골라 사용자 승인 후 짧은 동선으로 묶고 상황 변화에 맞춰 다시 계획하는 에이전트.

## 문제

### 누가 겪는 문제인가

- 특정 편의점, 세탁소, 마트나 주민센터에서 처리할 일이 쌓이는 사람
- 목적지 근처까지 갔다가 집에 돌아온 뒤에야 할 일을 떠올리는 사람
- 여러 심부름의 마감일, 영업시간, 준비물을 동시에 비교하기 어려운 사람

### 지금은 어떻게 버티고 있는가

- 할 일 앱에 장소 이름을 적거나 지도에 장소를 저장한다.
- 장소별 위치 알림을 하나씩 직접 설정한다.
- 외출 전에 할 일 목록과 지도를 번갈아 보며 머릿속으로 동선을 만든다.

### 왜 불편한가

- 위치 알림은 특정 장소에 도착했다는 사실은 알려주지만, 지금 처리할 여러 할 일을 함께 비교하지는 않는다.
- 가까워도 이미 문을 닫았거나 준비물을 두고 왔다면 알림이 도움이 되지 않는다.
- 반품 마감처럼 급한 일과 일반 장보기를 같은 우선순위로 다루기 어렵다.
- 모든 장소에서 알림을 보내면 알림 피로가 생겨 결국 무시하게 된다.

## 해결 방식

MVP는 실제 위치 권한 대신 작은 지도에서 현재 위치 핀을 움직인다. 장소와 운영시간은 모두 가상 데이터라고 표시하며, 에이전트는 사용자가 등록한 생활 심부름만 대상으로 후보를 고른다.

### 입력과 출력

- **할 일 입력**: 제목, 장소, 마감일, 예상 처리시간, 준비물, 완료 여부
- **사용자 설정**: 허용 우회시간, 한 번에 처리할 최대 개수, 알림을 받고 싶은 시간대
- **제안 카드**: 추천 할 일, 장소, 예상 추가시간, 영업 종료 시각, 마감까지 남은 시간, 준비물, 추천·제외 이유

### 판단 규칙

1. 문을 닫았거나, 마감이 지났거나, 준비물이 없다고 표시된 일은 후보에서 제외한다.
2. 현재 위치에서 사용자의 허용 우회시간 안에 있는 일만 남긴다.
3. `오늘 마감 → 3일 이내 마감 → 그 이후` 순서로 우선한다.
4. 같은 방향의 두 일을 묶었을 때 추가시간이 5분 이하라면 함께 제안한다.
5. 조건이 같으면 예상 추가시간이 짧은 일을 먼저 제안한다.

거리·시간 계산과 정렬은 일반 코드가 수행하고, LLM은 자연어 할 일 구조화와 추천 이유 설명만 담당한다.

### 에이전트 루프

1. **관찰**: 등록된 할 일, 가상 현재 위치, 현재 시각, 장소별 운영시간과 준비물 상태를 읽는다.
2. **판단**: 닫힌 장소와 실행 불가능한 일을 제외하고 마감, 우회시간, 묶음 가능성으로 후보를 정렬한다.
3. **사용자 확인**: 추천 이유, 예상 추가시간, 준비물과 제외된 할 일의 이유를 보여주고 동선 적용 여부를 묻는다.
4. **실행**: 사용자가 승인하면 순서가 있는 심부름 동선과 체크리스트를 만들고 선택한 일을 `진행 예정`으로 표시한다.
5. **재계획**: 장소가 휴무로 바뀌거나 현재 위치 핀이 이동하면 완료되지 않은 일만 다시 계산해 새 동선을 제안한다.

### 데모용 가상 데이터

실제 업체로 오인되지 않도록 장소명, 운영시간, 위치를 모두 데모 데이터라고 화면에 표시한다.

| 장소 | 데모 운영시간 | 연결된 할 일 |
| --- | --- | --- |
| 옷봄 세탁소 | 09:00~20:00 | 세탁물 수령 |
| 24편의점 A점 | 07:00~23:00 | 택배 반품 |
| 마을마트 | 10:00~22:00 | 세제 구매 |
| 행복동 주민센터 | 평일 09:00~18:00 | 서류 발급 |
| 24편의점 B점 | 07:00~23:00 | 택배 반품 대체 장소 |

### 90초 데모 시나리오

1. 마감일과 준비물이 설정된 생활 심부름 네 개가 있는 화면을 보여준다.
2. 발표자가 현재 시각을 `18:20`으로 두고 지도 핀을 세탁소와 편의점 근처로 이동한다.
3. 에이전트가 이미 문을 닫은 주민센터를 제외하고 `세탁물 수령 + 택배 반품`을 15분 우회 동선으로 묶어 제안한다.
4. 사용자가 준비물과 추천 근거를 확인한 뒤 동선을 승인한다.
5. 발표자가 세탁소를 `임시 휴무`로 바꾸면 에이전트가 반품만 먼저 처리하고 세탁물 수령을 다음 날로 미루는 계획을 만든다.

데모는 사용자가 **위치 이동 → 후보 발견 → 추천 근거 확인 → 동선 승인 → 장소 상태 변경 → 재계획**을 완료하면 성공이다.

### 안전장치

- 실제 GPS나 이동 이력을 수집·저장하지 않고 사용자가 움직인 데모 핀만 사용한다.
- 사용자가 등록하지 않은 장소나 구매 행동을 광고처럼 추천하지 않는다.
- 가상 영업시간과 실제 운영정보를 명확하게 구분한다.
- 동선 승인만으로 할 일을 완료 처리하지 않고 사용자가 직접 완료를 확인한다.
- 한 위치 변화당 제안 카드를 한 번만 보여주고 사용자가 거절한 제안은 같은 세션에서 반복하지 않는다.

## 핵심 기능

### 하루 MVP

- [ ] 장소, 마감일, 처리시간, 준비물이 포함된 생활 심부름 등록
- [ ] 가상 장소 5개와 이동시간 표가 포함된 고정 지도
- [ ] 현재 위치 핀과 현재 시각 변경 컨트롤
- [ ] 영업시간, 마감, 준비물, 허용 우회시간 기반 후보 필터링
- [ ] 가까운 할 일 두 개를 묶는 결정론적 우선순위 계산
- [ ] 추천·제외 이유와 예상 추가시간이 포함된 제안 카드
- [ ] 사용자 승인 후 순서형 동선과 체크리스트 생성
- [ ] 임시 휴무 이벤트에 따른 재계획

### 후속 확장

- [ ] 사용자가 허용한 경우 모바일 위치 알림 지원
- [ ] TMAP 또는 카카오모빌리티 API로 실제 우회시간 계산
- [ ] 캘린더와 주문 내역에서 사용자가 선택한 심부름 가져오기
- [ ] 실시간 영업정보와 휴무 변경 확인
- [ ] 이동 패턴을 기기에만 저장해 알림 빈도 개인화

### 이번 데모에서 제외

- 백그라운드 GPS, 실제 위치 권한과 이동 이력 저장
- 실제 푸시 알림과 지오펜스
- 상품 주문, 결제, 택배 반품 접수와 민원 신청
- 실제 업체의 영업시간 정확성 보장
- 광고·쿠폰·제휴 매장 추천

## 만들 수 있을까

### 필요한 기술/API

- 할 일 문장을 구조화하는 LLM
- 가상 장소, 운영시간, 할 일과 위치 간 이동시간이 담긴 작은 JSON 데이터
- 우선순위와 묶음 가능성을 계산하는 일반 코드
- 현재 위치 핀, 할 일, 추천 동선을 보여주는 SVG 또는 단순 지도 UI
- 장소 상태를 바꿔 재계획을 유발하는 데모 컨트롤

외부 지도 API 없이도 가상 지도와 고정 이동시간 표로 핵심 행동을 보여줄 수 있다. 실제 서비스 확장 시에는 TMAP 또는 카카오모빌리티 중 하나만 선택해 우회시간을 계산한다.

### 하루 구현 범위

1. 데모 지도, 장소와 할 일 JSON 작성: 1시간
2. 할 일 입력과 현재 위치·시각 컨트롤: 1시간 30분
3. 후보 필터링, 우선순위와 묶음 규칙: 1시간 30분
4. 제안 카드, 승인 동선과 재계획 UI: 2시간
5. 알림 중복 방지, 예외 흐름과 데모 리허설: 1시간

### 걸림돌과 대응

| 걸림돌 | 대응 |
| --- | --- |
| 실제 위치 감지는 권한과 배터리 문제가 있음 | 하루 MVP는 위치 이동 시뮬레이션만 사용한다. |
| 영업시간이 부정확하면 헛걸음할 수 있음 | 실제 업체를 쓰지 않고 모든 장소를 가상 데이터로 표시한다. |
| LLM이 비효율적인 동선을 만들 수 있음 | 후보 필터와 동선 순서는 결정론적 규칙으로 계산하고 LLM은 설명만 담당한다. |
| 추천이 너무 자주 나타날 수 있음 | 우회시간 한도, 알림 시간대, 세션당 중복 방지 규칙을 적용한다. |
| 할 일을 자동 완료해 상태가 어긋날 수 있음 | 승인 시 `진행 예정`으로만 바꾸고 완료는 사용자가 직접 확인한다. |

## 참고

### 공식 API·제품 문서

- [TMAP 대중교통 API](https://transit.tmapmobility.com/) — 대중교통과 도보 구간을 조합한 실제 경로 계산의 확장 후보.
- [카카오모빌리티 길찾기 API](https://developers.kakaomobility.com/guide/navi-api/start) — 다중 경유지와 다중 목적지의 거리·예상시간 계산을 제공하는 확장 후보.

### 유사 서비스

- [Apple 미리 알림의 위치 알림](https://support.apple.com/guide/reminders/add-dates-or-locations-to-reminders-remnd4b206fb/mac) — 특정 장소에 도착하거나 떠날 때 개별 알림을 받을 수 있다.
- [Todoist 위치 기반 미리 알림](https://www.todoist.com/help/todoist/features/use-location-reminders-in-todoist-uGcwH2AJ6) — 장소와 도착·출발 조건, 알림 반경을 할 일에 설정할 수 있다.

기존 위치 알림과 달리 이 아이디어는 **현재 처리 가능한 여러 심부름을 마감·영업시간·우회시간으로 비교해 한 동선으로 묶고, 장소 상태가 바뀌면 다시 계획하는 것**에 집중한다.
