# 휠체어·유모차 경로 에이전트

## 한 줄 요약
휠체어나 유모차로 이동하는 사용자가 출발지와 목적지, 피해야 할 장애물을 알려주면, AI가 접근성 태그를 근거로 이동 가능한 후보를 설명하고 장애물 발생 시 경로를 다시 만드는 에이전트.

## 문제

### 누가 겪는 문제인가

- 계단과 높은 턱을 이용할 수 없는 휠체어 사용자
- 엘리베이터나 경사로가 필요한 유모차 보호자
- 이동 전에 경로의 접근성 정보를 대신 확인해야 하는 동행자와 보호자

### 지금은 어떻게 버티고 있는가

- 일반 지도에서 최단 경로를 찾고 위성 사진, 거리뷰, 후기 등을 추가로 확인한다.
- 지하철역의 엘리베이터 위치와 건물 입구를 여러 사이트에서 따로 찾는다.
- 실제로 도착한 뒤 계단이나 고장 난 엘리베이터를 발견하면 현장에서 우회한다.

### 왜 불편한가

- 일반 최단 경로가 계단, 높은 턱, 급경사처럼 바퀴 이동이 어려운 구간을 포함할 수 있다.
- 휠체어와 유모차는 비슷해 보여도 허용 가능한 경사, 폭, 보조 가능 여부가 다르다.
- OpenStreetMap의 `wheelchair` 태그도 미기재 상태에는 기본값이 없으므로, 정보가 없다는 사실을 접근 가능하다는 뜻으로 해석하면 안 된다.
- 엘리베이터 고장처럼 상황이 바뀌면 출발 전에 확인한 경로가 무효가 될 수 있다.

## 해결 방식

MVP에서는 역 출구, 계단, 엘리베이터, 경사로, 턱이 포함된 작은 데모 지도를 사용한다. 경로 계산은 검증 가능한 규칙 기반 알고리즘이 담당하고, AI는 사용자의 조건을 묻고 결과를 설명하며 상황 변화에 맞춰 재탐색을 요청한다.

### 이동 프로필

- **휠체어**: 계단과 `wheelchair=no` 구간을 금지하고, 높은 턱을 제외한다. `wheelchair=limited` 또는 정보 없음은 경고 후 사용자가 허용할 때만 후보에 넣는다.
- **유모차**: 계단은 `ramp:stroller=yes`가 확인된 경우에만 허용한다. 엘리베이터와 별도 경사로를 우선하며, 사용자가 유모차를 들어 옮길 것이라고 가정하지 않는다.
- 두 프로필 모두 사용자가 허용 경사 수준과 동행 도움 여부를 직접 선택할 수 있다.

### 에이전트 루프

1. **관찰**: 출발지·목적지, 이동 프로필, 허용 경사, 동행 도움 여부와 지도 구간의 접근성 태그를 확인한다.
2. **판단**: 금지 구간을 먼저 제거한 뒤 남은 그래프에서 거리와 접근성 비용을 합친 경로를 계산한다. LLM이 직접 안전 판정을 계산하지 않는다.
3. **사용자 확인**: 추천 경로, 제외한 계단·턱, 정보가 부족한 구간, 데이터 확인 시각을 함께 보여준다.
4. **실행**: 사용자가 경로를 승인하면 단계별 이동 카드와 지도 위 경로를 표시한다.
5. **재계획**: 발표자가 엘리베이터 고장 이벤트를 주입하면 해당 구간을 즉시 제외하고, 우회 경로와 추가 이동시간을 다시 설명한다.

### 90초 데모 시나리오

1. 같은 출발지와 목적지를 두고 일반 최단 경로와 휠체어 프로필을 차례로 선택한다.
2. 일반 최단 경로에는 계단이 있지만, 에이전트는 `highway=steps` 근거로 이를 제외하고 엘리베이터 경로를 제안한다.
3. 사용자가 경로 설명과 데이터 확인 시각을 보고 승인한다.
4. 발표자가 경로의 엘리베이터를 `운행 중단`으로 바꾼다.
5. 에이전트가 경사로를 이용하는 우회 경로, 늘어난 거리와 `확인되지 않은 턱 1곳`을 보여주고 사용자에게 선택을 요청한다.

데모는 사용자가 **프로필 입력 → 접근성 근거 확인 → 경로 승인 → 장애물 발생 → 우회 경로 선택**을 완료하면 성공이다.

### 안전장치

- 경로를 `안전 보장`이 아닌 `확인된 데이터 기준 추천`으로 표현한다.
- 태그가 없거나 오래된 구간은 접근 가능으로 추정하지 않고 `정보 부족`으로 표시한다.
- 규칙 기반 경로 계산과 LLM 설명을 분리해 모델이 존재하지 않는 경사로나 엘리베이터를 만들어내지 못하게 한다.
- 데이터 출처와 마지막 확인 시각을 항상 노출한다.
- 휠체어와 유모차를 동일한 사용자로 취급하지 않고 프로필별 규칙과 설명을 구분한다.

## 핵심 기능

### 하루 MVP

- [ ] 출발지·목적지와 휠체어/유모차 프로필 선택
- [ ] 허용 경사 수준과 동행 도움 여부 입력
- [ ] 계단·엘리베이터·경사로·턱·정보 미확인 구간이 포함된 소규모 데모 그래프
- [ ] 접근성 규칙으로 금지 구간을 제거하는 결정론적 경로 계산
- [ ] 추천 경로와 제외된 구간의 태그·이유 표시
- [ ] 사용자 승인 후 단계별 이동 카드 표시
- [ ] 엘리베이터 고장 이벤트에 따른 경로 재계산
- [ ] 외부 데이터 호출 실패 시 번들 그래프만으로 전체 데모 지속

### 후속 확장

- [ ] Overpass API로 실제 지역의 OpenStreetMap 접근성 태그 가져오기
- [ ] 지하철 엘리베이터 운행 상태와 공공 접근성 데이터 결합
- [ ] 사용자 제보를 사진과 위치 증거가 포함된 검토 대기 상태로 수집
- [ ] 전동휠체어 크기, 경사 허용치, 노면 선호 등 세부 프로필 지원
- [ ] 보호자와 경로·도착 상태 공유

### 이번 데모에서 제외

- 전국 단위 실시간 보행 내비게이션
- 검증되지 않은 OpenStreetMap 데이터를 접근 가능하다고 단정하는 기능
- 실제 엘리베이터 고장 상태의 자동 수집
- 음성 턴바이턴 내비게이션과 상시 위치 추적
- 장애물 없는 이동이나 사용자의 안전을 보장하는 표현

## 만들 수 있을까

### 필요한 기술/API

- OpenStreetMap과 유사한 태그를 가진 작은 JSON 그래프
- `wheelchair`, `highway=steps`, `highway=elevator`, `ramp:*`, `incline`, `kerb`를 해석하는 프로필별 규칙
- Dijkstra 또는 A* 기반의 결정론적 경로 계산
- 조건 확인과 경로 근거 설명을 담당하는 LLM
- 노드·간선, 추천 경로, 차단 구간을 시각화하는 단순 SVG 또는 지도 UI

OpenStreetMap 태그와 Overpass API는 실제 서비스 확장의 데이터 후보지만, 하루 MVP는 데이터 누락과 네트워크 문제를 피하기 위해 검증된 번들 그래프를 사용한다.

### 하루 구현 범위

1. 두 개의 후보 경로가 있는 데모 그래프와 태그 정의: 1시간
2. 프로필 입력과 접근성 필터 규칙 구현: 1시간 30분
3. 경로 계산과 지도 시각화: 2시간
4. 근거 설명, 승인, 엘리베이터 고장 재계획: 1시간 30분
5. 안전 문구 검수, 실패 흐름, 데모 리허설: 1시간

### 걸림돌과 대응

| 걸림돌 | 대응 |
| --- | --- |
| 실제 접근성 태그가 없거나 오래됨 | MVP는 검증된 번들 그래프를 쓰고 정보 없음과 접근 가능을 명확히 구분한다. |
| 휠체어와 유모차의 요구가 다름 | 프로필별 금지·선호 규칙을 분리하고 사용자가 조건을 확인하게 한다. |
| LLM이 잘못된 안전 판단을 할 수 있음 | 경로 필터와 계산은 결정론적 코드로 처리하고 LLM은 질문과 설명에만 사용한다. |
| 실시간 엘리베이터 상태를 확보하기 어려움 | MVP에서는 발표자가 고장 이벤트를 주입하고 실제 연동이라고 주장하지 않는다. |
| 사용자가 경로를 과신할 수 있음 | 출처·확인 시각·정보 부족 구간을 노출하고 추천의 한계를 반복 안내한다. |

## 참고

### 공식·원천 데이터 문서

- [OpenStreetMap `wheelchair` 키](https://wiki.openstreetmap.org/wiki/Key:wheelchair) — `yes`, `limited`, `no`, `designated` 값과 미기재 상태에 기본값이 없음을 설명한다.
- [OpenStreetMap 보행 내비게이션 가이드](https://wiki.openstreetmap.org/wiki/Guidelines_for_pedestrian_navigation) — 계단, 엘리베이터, 경사로, 턱을 지도에서 표현하는 방법을 안내한다.
- [OpenStreetMap `highway=steps`](https://wiki.openstreetmap.org/wiki/Tag:highway%3Dsteps) — 계단과 휠체어·유모차용 경사로 관련 태그를 설명한다.
- [Overpass QL](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_QL) — OpenStreetMap 요소와 태그를 조회하는 질의 언어 문서.

### 유사 서비스

- [Google Maps 접근성 기능](https://support.google.com/maps/answer/6396990) — 대중교통 경로에서 휠체어 접근 가능 옵션을 선택할 수 있다.
- [Wheelmap](https://news.wheelmap.org/en/wp-content/uploads/sites/2/2019/10/Wheelmap_Mapper_Handout_EN.pdf) — 공공장소의 휠체어 접근성을 참여자가 표시하는 지도 서비스.

이 아이디어는 장소의 접근 가능 여부만 보여주는 데서 끝나지 않고, **개인 조건으로 경로를 설명하고 장애물 변화에 따라 다시 계획하는 것**에 집중한다.
