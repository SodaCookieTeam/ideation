# 답을 주지 않는 디버깅 튜터

## 한 줄 요약
학생이 AI가 준 수정 코드를 복붙하며 디버깅 능력을 못 쌓는 문제를, 정답 코드를 절대 말하지 않고 실행 결과를 근거로 질문만 던져 스스로 찾게 만들어 해결한다.

## 문제
- 대학 1학년 기초 프로그래밍 수강생, 코딩 부트캠프 초심자
- 지금은 코드를 붙여넣고 수정된 코드를 받아 그대로 복붙한다. 과제는 통과하지만 디버깅 능력이 안 쌓인다.
- 기존 학습 서비스의 힌트는 문제마다 사람이 미리 써둔 고정 힌트라서, 학생이 실제로 쓴 임의 코드에는 대응하지 못한다.

## 해결 방식
1. 학생 코드를 실행해 실제 에러와 오답 출력을 확보한다
2. **정답 코드 발설 금지** 제약 아래, 실행 결과를 근거로 단계별 유도 질문을 생성한다
3. 학생이 "그냥 고쳐줘"라고 요구해도 정답 대신 더 좁은 질문으로 되받는다
4. 몇 번의 질문 끝에 스스로 고쳤는지 "힌트 소비량"을 기록한다

## 핵심 기능
- [ ] 코드 실행으로 실제 에러 출력 확보 (최소 기능)
- [ ] 정답 발설 금지 제약 아래 유도 질문 생성
- [ ] 정답 요구를 거절하고 더 좁은 질문으로 되받기
- [ ] 힌트 소비량 기록

## 만들 수 있을까
- 필요한 기술: LLM 채팅, 코드 실행은 subprocess 타임아웃 격리 또는 컨테이너, 대화 상태 저장은 SQLite 수준
- 하루 안에 데모까지: **가능.** 로컬 코드 실행 샌드박스와 채팅 UI만 있으면 되고 외부 데이터가 필요 없다.
- 걸림돌
  - 모델이 유도 질문을 하다가 정답 코드를 흘리는 것이 가장 큰 위험이다. 출력 후처리로 코드 블록을 차단하는 안전장치가 필요하다.
  - 임의 코드 실행의 보안 격리. 시연은 화이트리스트 예제로 제한하는 게 안전하다.
  - 무한루프 예제는 타임아웃 처리가 필수다.

## 시연 장면
무한루프가 있는 파이썬 코드를 붙여넣는다. 튜터가 "루프 안에서 i는 언제 변하나요?"라고만 묻는다. 발표자가 일부러 **"그냥 고쳐줘"라고 요청하면 튜터가 정답 대신 더 좁은 질문으로 되받는다.** 마지막에 학생이 직접 고치고, 우측에 "힌트 3개로 해결"이 찍힌다.

## 참고
- Copilot과 일반 챗봇은 정답을 즉시 준다. Codecademy류 힌트는 문제마다 고정된 사람 작성 힌트다.
- 이 아이디어는 학생이 쓴 임의 코드에 대해 **실행 결과를 근거로 질문을 만든다.**
- 바이브코딩 해커톤에서 "AI가 답을 줘서 배우지 못한다"는 역설을 정면으로 다루는 서사가 있다. 발표에서 이 각도가 강하게 먹힌다.
