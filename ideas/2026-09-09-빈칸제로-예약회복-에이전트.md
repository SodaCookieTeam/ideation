# 빈칸제로: 취소 예약 회복 에이전트

## 한 줄 요약
예약형 소상공인의 당일 취소를 감지해 수신 동의한 대기 고객에게 조건에 맞는 슬롯을 순차 제안하고, 수락 시 슬롯과 예상매출을 안전하게 회복하는 에이전트다.

## 문제
- 미용실, 네일숍, 클래스 등 예약형 소상공인은 당일 취소가 생겨도 빈 슬롯을 다시 판매할 시간이 짧다.
- 점주는 대기 고객의 희망 서비스, 가능한 시간, 이동 거리를 수작업으로 비교하고 한 명씩 연락해야 한다.
- 여러 고객에게 동시에 제안하면 중복 확정이 생길 수 있고, 무차별 메시지는 고객 불만과 수신 거부를 만든다.
- 현재는 SNS 공지나 단체 메시지로 급히 채우거나 빈칸을 손실로 감수하지만 점주는 본업 중이라 빠르게 대응하기 어렵다.
- 업종별 취소율, 평균 객단가, 실제 메시지 전환율은 확인 못 함.

## 해결 방식
당일 취소 이벤트를 감지하면 동의된 대기 목록을 서비스·시간·거리 기준으로 정렬하고 점주 승인 후 한 명씩 제한 시간 제안을 보내며, 최초 수락자에게만 슬롯을 원자적으로 잠근다.

### 에이전트 루프
1. 에이전트가 모의 예약 캘린더에서 당일 취소와 회복 가능한 슬롯을 감지한다.
2. 사전 수신 동의, 희망 서비스, 가능한 시간, 이동 거리, 최근 제안 횟수를 기준으로 대상 고객을 필터링한다.
3. 민감속성을 제외하고 서비스 적합도, 시간 적합도, 거리, 메시지 피로도를 근거로 대기 고객의 순서를 계산한다.
4. 점주에게 예상 회복매출, 제안 대상, 정렬 근거, 메시지 내용을 보여주고 실행 승인을 받는다.
5. 승인 후 첫 고객에게 모의 제안을 보내고 수락 제한 시간 동안 다른 고객에게 같은 슬롯을 제안하지 않는다.
6. 거절하거나 시간이 만료되면 다음 고객에게 순차 제안한다.
7. 고객이 수락하면 트랜잭션 또는 비교 후 교환 방식으로 슬롯 상태를 다시 확인해 최초 수락자에게만 원자적으로 잠근다.
8. 예약 캘린더를 빨간 빈칸에서 녹색 예약으로 바꾸고 가정한 서비스 가격만큼 예상 손실매출을 회복매출로 갱신한다.

### 공정성과 안전장치
- 인종, 성별, 나이, 장애, 국적 등 민감속성은 수집·정렬·표시에 사용하지 않는다.
- 대기 등록 시 취소 슬롯 제안 수신 목적, 채널, 빈도에 별도 동의를 받고 언제든 철회할 수 있게 한다.
- 고객별 일일·주간 제안 횟수, 야간 발송 금지, 연속 거절 후 일시 중지로 스팸을 막는다.
- 실제 제안 실행 전 점주 승인을 요구하고 정렬 근거와 제외 이유를 감사 로그에 남긴다.
- 결제 여부와 최종 방문 확정은 에이전트가 추정하지 않고 점주 확인 상태로 분리한다.

## 핵심 기능
- [ ] 당일 취소 이벤트 감지와 빈 슬롯·예상 손실매출 표시
- [ ] 사전 수신 동의 및 서비스·시간·거리 조건 기반 대기 고객 필터링
- [ ] 민감속성을 배제한 후보 정렬과 근거 설명
- [ ] 점주 승인 후 제한 시간 순차 제안 모의 실행
- [ ] 수락·거절·만료 상태 처리와 다음 고객 자동 진행
- [ ] 중복 확정을 막는 원자적 슬롯 잠금
- [ ] 캘린더 상태와 예상 회복매출 실시간 갱신
- [ ] 발송 빈도 제한, 수신 철회, 감사 로그

### 3분 데모
1. 0:00~0:30에 예약 캘린더의 당일 예약 하나가 취소되며 슬롯이 빨간색으로 바뀌고 예상 손실매출이 표시된다.
2. 0:30~1:10에 에이전트가 동의된 고객만 남기고 서비스·시간·거리 기준으로 순서를 정하며 민감속성이 사용되지 않았음을 보여준다.
3. 1:10~1:35에 점주가 정렬 근거와 메시지를 검토하고 순차 제안을 승인한다.
4. 1:35~2:10에 첫 고객의 거절 후 다음 고객에게 모의 제안이 이동하고 두 수락 시도를 발생시켜 한 건만 잠기는 장면을 보여준다.
5. 2:10~3:00에 빨간 빈칸이 녹색 예약으로 바뀌고 예상 손실매출이 회복되며 캘린더와 감사 로그가 함께 갱신되는 장면을 보여준다.

## 만들 수 있을까
결론은 모의 캘린더·고객·메시지 데이터로 하루 안에 핵심 회복 루프와 원자적 잠금 장면을 시연할 수 있지만 실제 메시지, 결제, 예약 시스템 연동은 후속 검증이 필요하다는 것이다.

### 하루 MVP
- 취소 이벤트, 대기 고객, 서비스 가격이 담긴 로컬 모의 데이터를 사용한다.
- 규칙 기반 필터와 점수로 후보를 정렬하고 점주 승인, 순차 제안, 수락·거절·만료를 상태 머신으로 구현한다.
- 슬롯 버전 번호와 조건부 갱신으로 동시에 들어온 두 수락 중 하나만 성공하는 모습을 재현한다.
- 캘린더 색상, 손실·회복 예상매출, 제안 진행 상태, 감사 로그를 단일 웹 화면에 연결한다.
- 실제 전환율과 수익 개선 효과는 확인 못 했으므로 회복매출은 데모용 서비스 가격에 따른 예상치로 표시한다.

### 후속 확장
- 점주가 사용하는 예약·캘린더 시스템과 공식 메시지 제공자의 허용된 API를 연동한다.
- 고객이 선호 채널, 이동 가능 거리, 제안 시간대, 서비스 대체 가능 여부를 직접 관리하게 한다.
- 지점별 정책, 보증금, 대기 우선순위 실험, 실패 복구, 운영 지표 대시보드를 추가한다.
- 장기적으로는 취소뿐 아니라 점주가 확인한 노쇼 슬롯 회복을 검토하되 고객 분쟁 절차를 먼저 설계한다.

### 제외 범위
- 실제 SMS·메신저·이메일 발송과 실제 결제·환불·보증금 처리는 하루 MVP에서 제외한다.
- 고객 동의 없는 연락, 민감속성 기반 우선순위, 여러 고객에 대한 동시 확정 제안은 제외한다.
- 점주 승인 없는 자동 캠페인과 확정되지 않은 노쇼의 임의 취소는 제외한다.
- 실제 예약 플랫폼 API 연동은 제공 여부와 약관을 확인하지 못해 제외한다.

### 리스크와 대응
- 중복 예약은 잠금 전 슬롯 상태 재확인, 원자적 조건부 갱신, 실패 고객 안내로 방지한다.
- 스팸과 브랜드 훼손은 사전 동의, 빈도 제한, 조용한 시간, 즉시 수신 철회로 줄인다.
- 불공정한 정렬은 민감속성 배제, 사용 기준 공개, 점주 검토, 결정 로그로 점검한다.
- 예상매출의 과장은 실제 결제와 구분된 예상치 표시 및 계산 근거 공개로 막는다.
- 캘린더나 메시지 연동 장애는 재시도 횟수 제한, 중복 방지 키, 수동 복구 상태로 대응한다.
- 메시지·결제·예약 제공자의 실제 API, 비용, 약관은 확인 못 했으며 연동 전 별도 검토가 필요하다.

## 참고
- 실제 메시지, 결제, 예약 플랫폼 API는 확인 못 함.
- 고객 거리, 서비스 가격, 제안 제한 시간, 전환 결과는 데모를 위한 가정이다.
- 실제 운영 전 전자적 메시지 수신 동의, 개인정보 보관, 취소·환불 정책의 적용 요건을 확인해야 한다.
