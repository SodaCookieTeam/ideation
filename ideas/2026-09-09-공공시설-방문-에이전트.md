# 공공시설 방문 에이전트

## 한 줄 요약
전입신고를 위해 주민센터에 가야 하는지 헷갈리는 사용자가 자신의 상황을 알려주면, AI가 공식 정보를 근거로 온라인·방문 방법을 구분하고 사용자 승인 후 준비물과 방문 일정을 만들어 주는 에이전트.

## 문제

### 누가 겪는 문제인가

- 이사 후 전입신고를 처음 하거나 오랜만에 하는 사람
- 자신의 상황에서 온라인 신청이 가능한지, 주민센터를 방문해야 하는지 모르는 사람
- 업무시간, 준비물, 처리 기한을 여러 공식 페이지에서 따로 확인하기 어려운 사람

### 지금은 어떻게 버티고 있는가

- 포털에서 블로그와 과거 후기를 검색한다.
- 정부24와 주민센터 홈페이지를 오가며 필요한 정보를 직접 조합한다.
- 준비물이 확실하지 않으면 주민센터에 전화하거나 일단 방문한다.

### 왜 불편한가

- 같은 전입신고라도 본인·대리인 여부, 재외국민·해외체류 여부, 세대 구성에 따라 확인할 내용이 달라진다.
- 정부24는 전입신고를 인터넷과 방문으로 신청할 수 있다고 안내하지만, 온라인 대리인 신청은 허용하지 않는다.
- 방문 신청에는 유효한 신분증이 필요하며 개별 접수 가능 여부는 처리기관에 다시 확인해야 한다.
- 주민센터가 문을 닫은 시간에 방문하거나 준비물을 빠뜨리면 다시 가야 한다.
- 행정 규칙과 운영시간은 바뀔 수 있어 오래된 검색 결과를 그대로 믿기 어렵다.

## 해결 방식

MVP는 전입신고 한 종류와 강남구 주민센터 세 곳만 다룬다. 사용자의 주민등록번호나 신분증 이미지를 받지 않고, 최소한의 상황 정보로 온라인 처리 가능성과 방문 준비를 공식 원문과 함께 정리한다.

### 입력과 출력

- **입력**: 방문 목적, 실제 전입일, 신고자 본인 여부, 재외국민·해외체류 여부, 세대 합류 여부, 희망 처리 방법과 날짜
- **행동 카드**: 신고 기한, 온라인·방문 후보, 준비물, 선택한 주민센터의 주소·전화·운영시간, 공식 근거, 정보 확인일, 사용자 승인 상태

### 에이전트 루프

1. **관찰**: 사용자의 자연어 요청에서 전입일과 희망 방문일을 찾고, 처리 방법을 결정하는 데 필요한 조건이 빠졌는지 확인한다.
2. **판단**: 정부24에서 확인한 규칙을 결정표에 적용한다. 날짜 계산과 온라인·방문 후보 판정은 일반 코드로 처리하고 LLM은 의도 파악과 질문 생성만 담당한다.
3. **사용자 확인**: 추천 방법, 준비물, 신고 기한, 원문 근거와 확인일을 보여준다. 조건이 모호하면 가능하다고 추정하지 않고 관할 주민센터 확인을 요청한다.
4. **실행**: 사용자가 방문안을 승인하면 준비물 체크리스트와 `.ics` 방문 일정 파일을 만든다. 온라인안을 선택하면 정부24 공식 신청 페이지와 확인 절차를 제공한다.
5. **재계획**: 희망일이 휴무이거나 사용자 조건이 바뀌면 온라인 처리 또는 다음 운영일 방문으로 계획을 다시 만든다.

### 90초 데모 시나리오

1. 사용자가 `9월 8일 부모님 집으로 이사했고, 9월 12일 토요일에 역삼1동 주민센터에서 전입신고하고 싶다`고 입력한다.
2. 에이전트가 신고자 본인 여부, 재외국민·해외체류 여부, 기존 세대 합류 여부를 한 화면에서 묻는다.
3. 사용자가 `본인, 국내 거주, 기존 세대 합류`라고 답하면 정부24의 인터넷·방문 신청 안내, 신고 기한과 신분증 준비 근거를 보여준다.
4. 역삼1동 주민센터가 평일 09:00~18:00 운영이라 토요일 방문안은 제외하고, 정부24 온라인 신청과 9월 14일 월요일 방문안을 제시한다.
5. 사용자가 월요일 방문을 승인하면 신분증과 세대 상황 확인 항목이 담긴 체크리스트와 `.ics` 파일을 생성한다.

데모는 사용자가 **상황 입력 → 확인 질문 → 공식 근거 검토 → 처리 방법 선택 → 체크리스트·일정 생성**을 완료하면 성공이다.

### 안전장치

- 주민등록번호, 신분증 사진, 공동인증서와 같은 본인확인 정보를 수집하지 않는다.
- 공식 문서에 없는 자격이나 준비물을 추정하지 않고 `처리기관 확인 필요`로 표시한다.
- 규칙, 운영시간, 주소마다 출처와 확인일을 표시한다.
- 에이전트가 행정 처리를 보장하거나 사용자를 대신해 신고하지 않는다.
- 온라인 신청 또는 일정 생성 전 사용자가 원문 근거와 계획을 승인해야 한다.

## 핵심 기능

### 하루 MVP

- [ ] 전입일, 본인 신청 여부, 체류 상태, 세대 합류 여부 입력
- [ ] 자연어 요청에서 전입신고 의도와 희망일 추출
- [ ] 정부24 공식 내용을 옮긴 소규모 결정표로 온라인·방문 후보 판정
- [ ] 전입신고 기한, 준비물, 예외 조건과 원문 근거 표시
- [ ] 역삼1동·역삼2동·도곡1동 주민센터 프리셋 선택
- [ ] 운영시간과 희망일을 비교해 방문 가능 여부 계산
- [ ] 사용자 승인 후 체크리스트와 `.ics` 일정 파일 생성
- [ ] 외부 사이트 접속 실패 시 확인일이 표시된 번들 자료로 데모 지속

### 후속 확장

- [ ] 주민등록증 발급, 등·초본 발급 등 다른 주민센터 업무 추가
- [ ] 사용자가 선택한 지역의 공식 주민센터 정보를 실시간 조회
- [ ] 지도 API를 이용해 이동시간과 운영시간을 함께 고려
- [ ] 공식 안내 변경을 감지해 오래된 규칙의 사용을 차단
- [ ] 정부24 신청 진행 상태를 사용자가 직접 입력해 후속 할 일 관리

### 이번 데모에서 제외

- 정부24 로그인, 인증, 민원 신청 또는 제출
- 주민등록번호와 신분증 이미지 수집
- 전국 주민센터와 모든 민원 업무 지원
- 공식 근거가 없는 블로그·후기 기반 판단
- 법적 신고 완료 또는 접수 가능성 보장

## 만들 수 있을까

### 필요한 기술/API

- 자연어 요청을 정해진 입력 필드로 정리하는 LLM
- 정부24 전입신고 안내를 바탕으로 만든 작은 규칙 JSON
- 강남구 공식 페이지에서 확인한 주민센터 세 곳의 번들 데이터
- 날짜·요일·14일 기한을 계산하는 일반 코드
- 행동 카드, 근거 확인, 체크리스트와 `.ics` 다운로드를 제공하는 웹 UI

MVP에서 실시간 정부 API는 사용하지 않는다. 공식 페이지의 확인일과 링크를 포함한 번들 데이터로 판정하며, 실제 접수 가능 여부는 사용자가 정부24 또는 주민센터에서 다시 확인하도록 한다.

### 하루 구현 범위

1. 전입신고 규칙과 주민센터 번들 데이터 정리: 1시간 30분
2. 요청 입력·확인 질문 UI와 구조화: 1시간 30분
3. 결정표, 기한·운영시간 계산과 행동 카드: 2시간
4. 체크리스트와 `.ics` 생성: 1시간
5. 예외 흐름, 근거 링크 검수와 데모 리허설: 1시간

### 걸림돌과 대응

| 걸림돌 | 대응 |
| --- | --- |
| 행정 규칙이 변경될 수 있음 | 모든 규칙에 공식 출처와 확인일을 붙이고 오래된 자료는 자동 판정에 사용하지 않는다. |
| 세대 상황에 따른 예외가 많음 | MVP는 자주 쓰는 조건만 판정하고 그 밖의 경우는 주민센터 확인으로 종료한다. |
| LLM이 자격을 잘못 판단할 수 있음 | 판정은 고정 결정표와 일반 코드가 담당하고 LLM은 입력 정리와 설명만 수행한다. |
| 휴일·임시 운영시간이 바뀔 수 있음 | 번들 정보임을 표시하고 방문 전 공식 페이지나 전화 확인을 체크리스트에 넣는다. |
| 민감한 개인정보 입력 가능성 | 주민등록번호와 신분증 입력을 금지하고 예시 데이터만으로 데모한다. |
