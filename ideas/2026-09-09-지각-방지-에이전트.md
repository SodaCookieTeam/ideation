# 지각 방지 에이전트

## 한 줄 요약
약속이나 수업에 맞춰 출발 시간을 계산하기 어려운 사용자가 일정과 준비 조건을 입력하면, AI가 이동 경로와 준비 시간을 합쳐 행동 계획을 만들고 지연 상황에서 대안을 다시 제시하는 에이전트.

## 문제

### 누가 겪는 문제인가

- 수업, 면접, 병원 예약처럼 늦으면 곤란한 일정이 잦은 사람
- 이동시간뿐 아니라 씻기, 짐 챙기기, 주차 같은 준비시간까지 고려하기 어려운 사람
- 대중교통 지연이나 경로 변경이 생기면 새 계획을 빠르게 계산하기 어려운 사람

### 지금은 어떻게 버티고 있는가

- 지도 앱에서 예상 이동시간을 본 뒤 머릿속으로 준비시간을 빼서 알람을 맞춘다.
- 중요한 일정에는 감으로 넉넉한 알람을 여러 개 만든다.
- 지연이 생기면 지도 앱을 다시 열어 경로를 처음부터 검색한다.

### 왜 불편한가

- 지도 앱이 보여주는 이동시간과 실제로 준비를 시작해야 하는 시간은 다르다.
- 준비시간, 환승 여유, 도착 후 건물 입장 시간을 각각 계산해야 한다.
- 지연 상황에서는 기존 알람이 더 이상 유효하지 않지만 사용자가 직접 다시 판단해야 한다.
- 너무 이른 알람은 무시하게 되고, 너무 늦은 알람은 대안을 선택할 시간을 없앤다.

## 해결 방식

사용자가 일정 시각, 출발지·목적지, 준비시간, 도착 여유시간을 입력하면 에이전트가 이동 경로와 행동 시작 시간을 함께 계획한다.

### 에이전트 루프

1. **관찰**: 일정 시각과 장소, 사용자의 준비시간·도착 여유시간을 받고 TMAP 대중교통 API에서 경로별 예상 소요시간을 가져온다.
2. **판단**: `출발 마감 = 일정 시각 - 이동시간 - 도착 여유시간`, `준비 시작 = 출발 마감 - 준비시간`으로 계산하고 도착 가능성과 환승 수를 고려해 경로를 고른다.
3. **사용자 확인**: 선택한 경로, 준비 시작 시각, 출발 마감 시각, 계산 근거를 보여주고 알림을 만들지 묻는다.
4. **실행**: 사용자가 승인하면 준비 시작 알림과 출발 마감 알림을 데모 화면의 카운트다운에 등록한다.
5. **재계획**: 지연 이벤트가 들어오면 기존 계획으로 도착 가능한지 다시 계산하고, 대체 경로나 `지금 출발` 상태를 이유와 함께 제시한다.

### 90초 데모 시나리오

1. `15:00 약속`, 준비시간 `20분`, 도착 여유 `10분`과 프리셋 출발지·목적지를 입력한다.
2. API 또는 번들 응답에서 이동시간 `35분`인 경로를 받아 `13:55 준비 시작`, `14:15 출발 마감` 계획을 만든다.
3. 사용자가 계획을 승인해 두 개의 알림을 등록한다.
4. 발표자가 `15분 지연` 버튼을 누르면 기존 경로의 출발 마감이 `14:00`으로 당겨진다.
5. 에이전트는 이동시간 `40분`인 대체 경로와 `14:10 출발`을 비교하고, 대체 경로로 바꾸거나 즉시 준비하라는 선택지를 보여준다.

데모는 사용자가 **일정 입력 → 계산 근거 확인 → 알림 승인 → 지연 발생 → 새 계획 선택**을 완료하면 성공이다.

### 안전장치

- 모든 이동시간에는 조회 시각과 데이터 출처를 표시한다.
- 실시간 지연 데이터가 아닌 값은 `시뮬레이션` 또는 `시간표 기반`으로 명확히 표시한다.
- 위치나 일정이 빠졌을 때 임의로 채우지 않고 사용자에게 확인한다.
- 도착을 보장한다고 표현하지 않고, API 결과와 사용자가 정한 여유시간을 기반으로 한 예상이라고 안내한다.
- 택시 호출이나 상대방에게 메시지를 보내는 행동은 MVP에서 실행하지 않는다.

## 핵심 기능

### 하루 MVP

- [ ] 일정 시각, 준비시간, 도착 여유시간 입력
- [ ] 좌표가 저장된 프리셋 출발지·목적지 선택
- [ ] TMAP 대중교통 API 한 종류를 이용한 경로와 예상 소요시간 조회
- [ ] 준비 시작 시각과 출발 마감 시각 계산 및 근거 표시
- [ ] 사용자 승인 후 인앱 카운트다운 알림 등록
- [ ] `5분/15분 지연` 이벤트를 이용한 도착 가능성 재계산
- [ ] 대체 경로와 즉시 출발 중 선택할 수 있는 재계획 카드
- [ ] API 실패·쿼터 초과 시 번들 샘플 응답으로 데모 지속

### 후속 확장

- [ ] 캘린더에서 일정과 장소를 사용자 선택으로 가져오기
- [ ] 현재 위치와 실제 출발 여부를 기기에서 확인하기
- [ ] 버스·지하철 운행 상태와 날씨 변화를 반영하기
- [ ] 건물 입구 탐색, 주차, 엘리베이터 대기 등 개인별 완충시간 학습하기
- [ ] 사용자가 승인하면 지각 예상 메시지 초안 만들기

### 이번 데모에서 제외

- 주소를 좌표로 변환하는 별도 지오코딩 API
- 상시 GPS 추적과 백그라운드 위치 수집
- 전국 모든 교통수단의 실시간 지연 감지
- 자동 택시 호출, 결제, 상대방 메시지 전송
- 교통 상황과 관계없이 도착 시각을 보장하는 표현

## 만들 수 있을까

### 필요한 기술/API

- 프리셋 좌표와 TMAP 대중교통 API의 경로 탐색 또는 요약정보 API
- 일정 조건과 경로 후보를 비교하고 재계획 이유를 설명하는 LLM
- 시각 계산, 경로 카드, 인앱 알림을 보여주는 웹 UI
- API 실패 시 사용할 고정 요청·응답 JSON

TMAP 대중교통 API는 출발지·목적지 좌표를 받아 대중교통과 도보가 조합된 경로를 제공한다. 현재 공개 안내의 무료 요금제는 일일 호출 수가 적으므로, 발표 데모는 사전에 저장한 응답으로도 동일하게 동작해야 한다. 실시간 지연 피드는 MVP에 포함하지 않고 발표자가 상태 변화를 주입한다.

### 하루 구현 범위

1. 일정·준비 조건 입력과 프리셋 장소 UI: 1시간
2. TMAP 요청 및 번들 샘플 응답 연결: 1시간 30분
3. 시각 계산과 경로 선택 규칙 구현: 1시간 30분
4. 승인·알림·지연 이벤트·재계획 UI: 2시간
5. 실패 대체 흐름, 데모 리허설, 화면 정리: 1시간

### 걸림돌과 대응

| 걸림돌 | 대응 |
| --- | --- |
| API 키 발급이나 호출 제한 | 행사 전에 키를 확인하고 모든 데모 경로의 샘플 응답을 함께 번들한다. |
| 주소 입력에는 지오코딩이 추가로 필요함 | MVP에서는 좌표가 저장된 장소 2~3개만 선택하게 한다. |
| 시간표 기반 결과와 실제 지연이 다를 수 있음 | 데이터 성격을 화면에 표시하고, 지연은 시뮬레이션 이벤트로만 처리한다. |
| LLM이 시각 계산을 틀릴 수 있음 | 시각 계산은 일반 코드로 수행하고 LLM은 조건 확인과 설명에만 사용한다. |
| 일정과 위치 정보가 민감함 | MVP는 계정 없이 세션 안에서만 입력값을 사용한다. |
