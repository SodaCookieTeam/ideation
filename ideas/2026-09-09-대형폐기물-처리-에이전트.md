# 버림비서: 대형폐기물 처리 실행 에이전트

## 한 줄 요약
자취생이 버릴 물건의 사진과 주소를 입력하면 재사용·기부·재활용·대형폐기물 처리 경로를 비교하고, 관할 규정에 맞춘 신고서 초안·예상 비용·배출 일정과 알림을 만들어 사용자 승인까지 준비한다.

## 문제

### 누가 겪는 문제인가

- 이사나 계약 종료를 앞두고 가구와 대형 생활용품을 빠르게 정리해야 하는 자취생
- 중고 판매, 기부, 재활용, 대형폐기물 신고 중 무엇이 맞는지 모르는 1인 가구
- 품목명, 규격, 배출 장소와 날짜를 관할 시스템에 다시 입력해야 하는 사용자

### 지금은 어떻게 버티고 있는가

- 사진을 보고 중고 거래 가능성을 감으로 판단한 뒤, 팔리지 않으면 관할 대형폐기물 안내를 다시 검색한다.
- 비슷한 품목명을 목록에서 골라 수수료를 추정하고 신고 사이트에 주소·규격·날짜를 직접 입력한다.
- 수거일과 배출 시간을 메모하거나 기억하다가 놓치고, 이사 당일 급하게 다른 처리 방법을 찾는다.

### 왜 불편한가

- 멀쩡한 물건도 시간 부족 때문에 곧바로 폐기되어 재사용 기회를 잃는다.
- 같은 의자나 선반도 재질·크기·분해 여부와 관할 규정에 따라 처리 경로와 비용이 달라질 수 있다.
- 사진만으로 정확한 품목과 규격을 확정하기 어렵고, 잘못 신고하면 미수거 또는 재신고로 이어질 수 있다.
- 비교, 규정 확인, 신고 정보 작성, 배출 일정 관리가 서로 다른 화면과 시간대에 흩어져 있다.

## 해결 방식

사진과 주소를 받은 뒤 폐기부터 권하지 않고 **재사용 → 기부 → 재활용 → 대형폐기물 신고** 순서로 가능한 경로를 비교한다. 사용자가 비용, 남은 기간, 운반 가능 여부를 선택하면 근거가 확인된 후보를 정렬하고, 최종 선택에 필요한 신고서 초안과 일정만 준비한다. 실제 신고·결제는 사용자 승인과 관할 시스템의 최신 정보 확인 뒤 사용자가 수행한다.

### 에이전트 루프

1. **관찰**: 사진에서 품목·재질·상태 후보를 추출하고, 사용자가 주소와 처리 희망일을 입력한다.
2. **보완 질문**: 높이·너비·길이, 작동 여부, 오염·파손, 엘리베이터 유무, 직접 운반 가능 여부를 묻는다. 사진으로 알 수 없는 규격을 추정값으로 확정하지 않는다.
3. **관할 확인**: 주소를 데모용 관할 데이터에 매핑하고 규칙 버전과 확인일을 표시한다. 주소가 경계에 있거나 매핑되지 않으면 관할을 사용자에게 다시 확인시킨다.
4. **경로 비교**: 규칙 기반 점수로 재사용 판매, 기부, 재활용, 대형폐기물 후보를 비용·소요시간·운반 부담·마감 가능성 기준으로 비교한다. LLM은 후보 설명을 맡고 규정과 비용을 만들어내지 않는다.
5. **선택과 승인**: 사용자가 처리 경로를 고르면 필요한 행동, 마감 시점, 실패 시 다음 후보를 보여주고 실행 계획을 승인받는다.
6. **실행 준비**: 대형폐기물을 선택한 경우 관할 품목명, 규격, 예상 수수료, 주소, 희망 배출일이 들어간 신고서 초안을 만든다. 재사용·기부를 선택하면 게시 초안 또는 문의 체크리스트를 만든다.
7. **일정 추적**: 승인한 계획에 따라 촬영·문의·신고·배출 알림을 만들고, 판매나 기부가 정해진 시점까지 실패하면 사용자에게 다음 처리 경로 전환을 제안한다.
8. **완료 확인**: 사용자가 실제 관할 화면에서 비용·일정을 재확인하고 신고·결제를 완료한 뒤 접수번호를 직접 입력해야 `신고 완료`로 표시한다. 수거 후 사용자 확인으로 작업을 종료한다.

### 경로 비교 원칙

- 상태가 양호하고 처리 기한이 충분하면 재사용 판매와 기부를 먼저 보여준다.
- 오염·파손으로 재사용이 어렵더라도 재질별 재활용 가능 여부를 규정 근거와 함께 검토한다.
- 대형폐기물 신고는 가장 확실한 기본값이 아니라 비용과 일정이 확인된 하나의 후보로 취급한다.
- 후보가 성립하려면 수거 지역, 품목 상태, 운반 조건, 신청 마감 중 확인된 조건을 모두 표시한다.
- 확인하지 못한 비용, 수거 가능일, 기관 접수 여부는 `확인 못 함`으로 남기고 임의로 채우지 않는다.

### 3분 데모

1. 0:00~0:30 — 이사를 사흘 앞둔 사용자가 작은 책상 사진과 데모 주소를 입력한다.
2. 0:30~1:00 — 에이전트가 책상 후보를 보여주고 사용자가 규격, 파손 여부, 직접 운반 불가를 답한다.
3. 1:00~1:30 — 재사용 판매, 기부, 대형폐기물 세 경로를 예상 비용·소요시간·운반 부담과 근거로 비교한다.
4. 1:30~2:00 — 사용자가 `내일까지 기부 문의, 실패하면 대형폐기물 신고` 계획을 승인하고 알림을 생성한다.
5. 2:00~2:30 — 발표자가 기부 불가 이벤트를 넣으면 에이전트가 데모 관할 규정에서 책상 품목과 예상 수수료를 찾아 신고서 초안을 채운다.
6. 2:30~3:00 — 사용자는 실제 제출 전 확인 항목을 검토한다. 결제 버튼 대신 `관할 시스템에서 최신 비용·일정 확인 필요` 경고와 승인 단계를 보여주고, 모의 접수번호 입력 후 배출 알림이 생성된다.

데모는 사용자가 **사진·주소 입력 → 처리 경로 비교 → 계획 승인 → 실패 시 대안 전환 → 신고 초안 확인 → 일정 생성**을 완료하면 성공이다.

### 안전장치

- 사진 분류 결과를 확정 품목이 아닌 후보로 표시하고, 규격·재질·상태를 사용자가 수정하게 한다.
- 주소는 관할 판정과 일정 생성에 필요한 범위만 사용하며 화면 공유용 데모에서는 실제 거주지 대신 가상 주소를 쓴다.
- 비용과 배출 가능일에는 규칙 출처, 적용 지역, 확인일을 표시하고 최신 관할 시스템과 다르면 관할 정보가 우선임을 안내한다.
- 신고서 초안과 알림 생성은 가능하지만 사용자 승인 없이 실제 신고, 결제, 기부 예약, 중고 게시를 실행하지 않는다.
- 모델이 품목 코드, 수수료, 수거일을 생성하지 못하도록 구조화된 데모 규칙에 존재하는 값만 사용한다.
- 재사용 후보는 안전·위생·리콜 여부를 보장하지 않으며, 전기제품 등 상태 확인이 필요한 품목은 별도 점검을 요구한다.
- 주소가 모호하거나 품목이 규정표에 없으면 가장 비슷한 항목으로 자동 확정하지 않고 관할 기관 확인 항목으로 남긴다.

## 핵심 기능

### 하루 MVP

- [ ] 사진 업로드와 품목·재질·상태 후보 추출
- [ ] 주소 입력과 두 개 데모 지역의 관할 규칙 선택
- [ ] 규격·파손·처리 기한·운반 가능 여부 보완 질문
- [ ] 재사용·기부·재활용·대형폐기물 경로 비교 카드
- [ ] 근거가 있는 비용·소요시간·운반 부담 표시
- [ ] 사용자 조건에 따른 1순위 계획과 실패 시 대안 제안
- [ ] 대형폐기물 신고서 초안과 제출 전 확인 체크리스트
- [ ] 계획 승인 후 문의·신고·배출 일정과 알림 생성
- [ ] 기부 실패 이벤트에 따른 대형폐기물 경로 전환
- [ ] 모델 호출 실패 시 수동 품목 선택과 번들 규칙으로 데모 지속

### 후속 확장

- [ ] 실제 관할별 품목 코드·수수료·수거 일정 데이터 연계
- [ ] 지역 재사용 센터와 기부 기관의 수거 조건·예약 가능 시간 연계
- [ ] 중고 거래 수요와 남은 처리 기간을 반영한 가격·마감 제안
- [ ] 여러 물건을 묶어 차량·엘리베이터·배출 공간 제약까지 최적화
- [ ] 관할 시스템의 사용자 승인형 신고·결제 연결
- [ ] 접수번호 기반 수거 상태 확인과 미수거 대응 안내
- [ ] 규정 변경 감지, 관리자 검토, 적용일별 버전 관리

### 이번 데모에서 제외

- 사용자 승인 없는 실제 신고·결제·예약·중고 게시 자동 실행
- 전국 지자체 규정과 실시간 수거 가능일 지원
- 사진만으로 정확한 규격·품목 코드·제품 안전성을 확정하는 기능
- 기부 기관의 실제 접수 가능 여부나 중고 판매 성공 보장
- 폐기물 운반 대행, 건물 밖 반출, 불법 투기 가능 장소 안내
- 주소와 결제 정보를 외부 서비스에 자동 전송하는 기능

## 만들 수 있을까

### 필요한 기술/API

- 품목·재질·상태 후보를 추출하는 멀티모달 모델
- 주소를 데모 관할로 연결하는 우편번호 또는 행정구역 매핑 데이터
- 품목 코드, 규격 기준, 수수료, 배출 조건, 확인일이 포함된 구조화 규칙 JSON
- 처리 경로를 비용·시간·운반 부담으로 비교하는 결정론적 점수 로직
- 신고서 초안, 승인 단계, 일정과 로컬 알림을 보여주는 웹 UI

실제 지자체 대형폐기물 API의 존재, 주소별 온라인 신고 형식, 수수료·수거일 실시간 조회, 외부 시스템으로의 자동 제출·결제 가능 여부는 **확인 못 함**. 기부 기관이나 재사용 센터의 예약 API 존재 여부도 **확인 못 함**. 하루 MVP는 두 개 가상 관할의 번들 규칙과 모의 접수번호를 사용한다.

### 하루 구현 범위

1. 두 지역·다섯 품목의 데모 규칙과 비교 기준 작성: 1시간
2. 사진 분류와 보완 질문 화면: 1시간 30분
3. 네 가지 처리 경로 비교와 계획 승인: 1시간 30분
4. 신고서 초안, 비용·일정 근거, 확인 체크리스트: 1시간
5. 알림과 기부 실패 후 대안 전환: 1시간
6. 규정 변경·오분류 실패 흐름과 데모 리허설: 1시간

### 걸림돌과 대응

| 걸림돌 | 대응 |
| --- | --- |
| 사진만 보고 책상·선반 등 비슷한 품목을 오분류함 | 여러 후보와 판단 근거를 보여주고 사용자가 관할 품목명을 직접 선택하게 한다. |
| 크기·재질을 잘못 추정해 비용이 달라짐 | 사진으로 수치를 만들지 않고 사용자 실측을 요구하며, 미측정 상태에서는 비용 범위를 확정하지 않는다. |
| 주소가 관할 경계이거나 행정동과 서비스 구역이 다름 | 관할 후보와 근거를 표시하고 실제 신고 화면에서 사용자가 다시 확인하게 한다. |
| 수수료·품목 코드·배출 규정이 변경됨 | 규칙 출처·버전·확인일을 표시하고 오래된 데이터에는 경고한다. 실제 제출 전 최신 관할 시스템 확인을 필수로 둔다. 최신 규정은 확인 못 함. |
| 기부·재사용 가능성을 과대평가해 이사 기한을 놓침 | 사용자 마감에서 역산한 전환 시점을 정하고, 실패 이벤트가 오면 승인 후 다음 후보로 이동한다. |
| 자동 제출이 중복 신고나 잘못된 결제로 이어짐 | MVP에서는 제출·결제를 하지 않고 초안만 생성하며, 후속 연동도 사용자 승인과 접수 결과 확인을 요구한다. |
| 주소와 사진이 불필요하게 외부로 전송됨 | 데모는 가상 주소와 준비 사진을 쓰고, 실제 서비스에서는 최소 수집·보관 기간·전송 대상을 명시한다. |
| 규정표에 없는 품목을 유사 항목으로 단정함 | `관할 확인 필요`로 남기고 유사 품목은 질문 후보로만 제공한다. |

- 버림비서는 가구·대형 물품을 대상으로 **재사용부터 폐기까지 처리 경로를 비교하고, 신고 초안과 마감 일정으로 실행을 이어가는 것**에 집중한다.
- 실제 지자체 대형폐기물 API, 자동 제출·결제 지원, 기부·재사용 기관 예약 API의 존재 여부는 확인 못 함.
