# 계약 조항 3자 대립 검토실

## 한 줄 요약
자취방 계약서나 용역 계약을 처음 읽는 학생이 무엇이 불리한지 모르는 문제를, 내 편 대리인과 상대 편 대리인과 조문 검색관이 조항별로 대립하게 만들어 진짜 협상 지점만 남겨 해결한다.

## 문제
- 원룸 임대차, 알바·프리랜스 용역, 공모전 참가 약관에 서명하는 학생
- 특약 문구를 그냥 읽고 넘기거나 커뮤니티에 "이거 괜찮나요"를 물어 답이 갈린다.
- 이사 나갈 때 원상복구비로 싸우고 나서야 그 조항의 뜻을 안다.

## 해결 방식
에이전트 역할을 나눠 조항마다 대립시킨다.

1. **조항 분해관** — 계약서를 조항 단위로 쪼갠다
2. **내 편 대리인** — 각 조항의 불리한 해석과 협상 문구를 제안한다
3. **상대 편 대리인** — 그 해석이 과장인 이유를 반박하고 관행 근거를 댄다
4. **조문 검색관** — 관련 법 조문·표준계약서 문구를 인용한다. 못 찾으면 "근거 없음, 관행 주장"으로 낙인
5. **정리관** — 조항별 위험도 3단계와 대립 요약을 낸다

사람은 조항별로 "협상 가능 / 포기" 태그를 달고, 태그를 반영한 협상 요청 문구를 다시 받는다.

### 왜 역할을 나누는가
LLM 한 번 호출로 "이 계약서 검토해줘"를 시키면 모든 조항에 "위험합니다"가 붙어 전부 빨간불이 된다. 어디가 진짜 협상 지점인지 가려지지 않는다. 반대 대리인이 과장을 깎아내고 조문 검색관이 근거 유무를 나눠야 위험도에 신뢰가 생긴다.

## 핵심 기능
- [ ] 조항 단위 대립 뷰 — 내 편 / 상대 편 / 조문 근거 3칸 (최소 기능)
- [ ] 근거 있는 위험과 관행 주장 구분 표시
- [ ] 사람이 태그를 달면 협상 요청 문장 생성
- [ ] 위험도 3단계 정리표

## 만들 수 있을까
- 필요한 기술: LLM(역할별 프롬프트 분리), PDF 텍스트 추출, 임베딩 검색, 표준계약서·법 조문 텍스트
- 하루 안에 데모까지: **가능.** 조항 수를 3~5개로 잘라 병렬 처리하면 대기 시간이 짧다. 검색 대상은 미리 받아둔 표준계약서와 조문 텍스트로 한정한다.
- 국가법령정보센터의 법령 데이터 API 신청 요건과 이용 조건은 **확인 못 함.** 데모는 사전에 내려둔 문서로 진행한다.
- 걸림돌
  - 법률 자문으로 오인될 여지가 있다. 화면에 "정보 제공이며 법률 자문이 아님, 최종 확인은 전문 상담" 고정 문구를 넣고, 판정 표현을 "불법/무효" 대신 "불리할 수 있음 / 확인 필요"로 못 박는다.
  - 조문 검색 품질이 낮으면 전부 "관행 주장"으로 떨어져 볼거리가 준다.
  - 스캔 이미지 계약서는 OCR이 필요해 하루 범위를 넘는다. 텍스트 PDF로 고정한다.

## 시연 장면
실제 원룸 특약 문구를 붙여넣는다. 조항 카드가 3칸으로 갈라지며 내 편이 "원상복구 범위가 무한정"이라 주장하고, 상대 편이 "통상 마모는 제외가 관행"이라 반박한다. 조문 검색관이 표준계약서 문구를 인용해 붙이자 위험도가 **빨강에서 주황으로 내려간다.** 사람이 "협상 가능"을 누르면 임대인에게 보낼 한 문단이 뽑힌다.

## 참고
- 약관 요약 서비스는 위험 조항을 나열하는 데서 끝난다. 로톡 같은 상담 서비스는 사람이 붙어 시간과 비용이 든다.
- 이 아이디어는 상대 편 대리인이 반론을 걸어 과장을 깎고, 사람 태그가 협상 문구로 이어지는 왕복 구조다.
- 이 아이디어는 12개 분야 중 6개 분야에서 독립적으로 나왔다. 수요 신호가 강하다는 뜻이지만 그만큼 흔한 발상이므로, **대립 구조**를 차별점으로 앞세워야 한다.
- 기존 아이디어인 민원 문서 작성 에이전트와는 다르다. 그쪽은 사고가 터진 뒤 기관에 내는 문서, 이쪽은 서명 전 검토다.
