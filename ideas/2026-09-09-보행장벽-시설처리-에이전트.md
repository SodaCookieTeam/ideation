# 길막제로: 보행장벽 시설처리 에이전트

## 한 줄 요약
휠체어·유모차·보행보조기 사용자가 일시적 보행장벽을 발견하면 사진과 위치로 영향 범위를 판정하고 우회 정보를 안내한 뒤, 담당 배정부터 제거 재검증까지 추적하는 모의 시설관리 티켓을 생성한다.

## 문제

### 누가 겪는 문제인가

- 경사로와 엘리베이터를 반드시 이용해야 하는 휠체어 사용자
- 계단이나 좁은 통로를 피해야 하는 유모차 보호자와 보행보조기 사용자
- 현장 제보를 접수하고 시설 담당 부서에 전달해야 하는 공공시설 운영자와 관리 인력

### 지금은 어떻게 버티고 있는가

- 경사로 위 적치물, 공사 펜스, 고장 난 엘리베이터를 현장에서 발견한 뒤 돌아가거나 주변 사람에게 도움을 요청한다.
- 민원 앱이나 전화로 위치와 상황을 다시 설명하지만, 어느 시설의 어떤 장벽인지 담당자가 재확인해야 한다.
- 처리 완료 안내를 받아도 실제 통행이 복구됐는지 제보자가 확인할 방법이 부족하다.

### 왜 불편한가

- 고정된 계단·경사와 달리 일시적 장벽은 지도 데이터에 반영되기 전에 생기고 사라진다.
- 같은 장애물도 휠체어에는 통행 불가, 유모차에는 도움을 전제로 한 제한 통행처럼 영향이 다를 수 있다.
- 사진, 위치, 시설 유형, 영향받는 이동 프로필이 분리되어 전달되면 담당 배정과 현장 확인이 늦어진다.
- 시설 측의 `처리 완료`와 실제 사용자의 `다시 통행 가능` 사이에 검증 공백이 있다.

## 해결 방식

경로 추천 자체가 아니라 **현장 장벽 발견 → 구조화된 신고 → 담당 배정 → 처리 → 재촬영 검증 → 종료**의 폐쇄 루프에 집중한다. MVP에서는 실제 민원 시스템에 제출하지 않고, 검증된 데모 장소와 모의 시설관리 보드에서 티켓 수명주기를 보여준다.

### 에이전트 루프

1. **관찰**: 사용자가 사진을 촬영하고 지도에서 위치를 확인한다. Vision 모델이 경사로 적치물, 공사 펜스, 고장 표시가 있는 시설 등 후보 유형과 가려진 통행 폭을 추출한다.
2. **질문**: 모델의 확신이 낮거나 사진만으로 시설 상태를 알 수 없으면 사용자가 장애물 유형, 지속 여부, 통행 가능 폭을 확인한다.
3. **판정**: 결정론적 규칙이 장애물 유형과 통행 조건을 휠체어·유모차·보행보조기 프로필에 대조해 `통행 불가`, `제한`, `영향 확인 필요`로 분류한다. LLM이 안전 여부를 단독 결정하지 않는다.
4. **즉시 대응**: 현재 위치를 기준으로 검증된 데모 우회 구간과 추가 이동량을 제시하되, 현장 안전을 보장하는 경로라고 표현하지 않는다.
5. **신고 초안**: 위치, 최초 사진, 유형, 영향 프로필, 발견 시각, 사용자 확인 내용을 담은 모의 시설관리 티켓을 만든다. 사용자가 내용을 승인해야 접수 상태로 전환한다.
6. **담당 배정**: 시설 유형·소유 주체가 미리 정의된 데모 규칙에 따라 담당 큐를 지정하고, 모호하면 `수동 분류 필요` 큐로 보낸다.
7. **처리와 재검증**: 담당자가 처리 완료 후보로 바꾸면 사용자가 같은 위치에서 다시 촬영한다. 전후 사진과 사용자 확인을 모두 통과해야 티켓을 종료하며, 불일치하면 재개한다.

### 티켓 상태

`초안 → 사용자 승인 → 접수 → 담당 배정 → 처리 중 → 재검증 대기 → 종료` 순서로 진행한다. 자동 분류에 실패한 티켓은 `수동 분류 필요`, 재촬영에서 장벽이 남아 있으면 `재개` 상태로 이동한다.

### 3분 데모

1. 0:00~0:30 — 휠체어 프로필을 선택하고 경사로 앞 적치물 사진을 촬영한다.
2. 0:30~1:00 — 모델이 `경사로 적치물` 후보와 휠체어 통행 불가 영향을 제시하고, 사용자가 위치·유형을 수정하거나 승인한다.
3. 1:00~1:30 — 에이전트가 검증된 데모 우회 구간과 추가 이동량을 표시하고, 사진·위치·유형·영향 프로필이 채워진 티켓 초안을 만든다.
4. 1:30~2:00 — 사용자가 제출을 승인하면 데모 규칙이 시설관리 담당 큐에 배정하고 상태 보드가 `처리 중`으로 바뀐다.
5. 2:00~2:30 — 발표자가 적치물을 치우고 티켓을 `재검증 대기`로 전환한다.
6. 2:30~3:00 — 사용자가 같은 장소를 재촬영한다. 전후 비교와 사용자 확인 후 티켓이 종료되고, 장벽이 남은 비교 사진에서는 티켓이 재개되는 흐름도 보여준다.

데모는 사용자가 **장벽 촬영 → 영향 확인 → 신고 승인 → 담당 배정 → 제거 후 재촬영 → 티켓 종료**를 완료하면 성공이다.

### 안전장치

- 사진 판정은 `후보`로 표시하고, 위치·유형·통행 상태를 사용자가 수정한 뒤 승인하게 한다.
- 사람의 얼굴, 차량 번호판, 집 주소처럼 신고에 불필요한 정보는 저장 전 가림 처리하고 원본 보관 여부를 명시한다.
- `영향 없음` 판정도 통행 가능이나 안전을 보장하지 않으며, 시야가 가린 사진은 재촬영을 요구한다.
- 우회 정보는 검증된 데모 그래프에서만 계산하고, 존재하지 않는 통로나 시설을 LLM이 생성하지 못하게 한다.
- 담당 배정이 불확실하면 임의 부서에 자동 제출하지 않고 `수동 분류 필요`로 남긴다.
- 시설 측 처리 완료만으로 닫지 않고 재촬영 비교와 사용자 확인을 요구한다. 재방문이 불가능하면 `재검증 못 함`으로 남긴다.
- 실제 긴급 위험은 일반 시설 티켓 대신 현장 접근 중지와 관할 긴급 연락 수단 확인을 안내한다.

## 핵심 기능

### 하루 MVP

- [ ] 사진 업로드와 지도 기반 위치 확인
- [ ] 세 가지 데모 장벽 유형 분류: 경사로 적치물, 공사 펜스, 고장 표시 시설
- [ ] 휠체어·유모차·보행보조기 프로필별 영향 규칙
- [ ] 불확실한 분류를 사용자가 수정·승인하는 화면
- [ ] 검증된 소규모 그래프의 우회 정보와 추가 이동량 표시
- [ ] 위치·사진·유형·영향 프로필·시각을 포함한 모의 티켓 생성
- [ ] 데모 규칙 기반 담당 큐 배정과 티켓 상태 보드
- [ ] 제거 후 재촬영, 전후 비교, 종료 또는 재개 흐름
- [ ] 모델 호출 실패 시 준비된 사진과 수동 유형 선택으로 데모 지속

### 후속 확장

- [ ] 시설물 식별자와 공공 자산 관리 정보 연계
- [ ] 여러 제보의 위치·시간·이미지 유사도 기반 중복 티켓 병합
- [ ] 실제 담당 기관의 접수 결과와 상태 변경 동기화
- [ ] 기기 내 얼굴·번호판 자동 가림과 원본 자동 폐기 정책
- [ ] 반복 장벽과 평균 처리시간을 보여주는 시설관리 대시보드
- [ ] 당사자 외 제3자의 현장 재검증과 접근성 단체 검토 흐름

### 이번 데모에서 제외

- 전국 단위 실시간 장벽 지도와 상시 카메라 감시
- 실제 지자체·시설관리 시스템으로 민원 자동 제출
- 사진 한 장만으로 시설 고장 원인이나 법적 책임을 확정하는 기능
- 검증되지 않은 공개 경로를 안전한 우회로라고 보장하는 기능
- 사용자 승인 없는 위치·사진 전송과 담당 부서 자동 확정
- 시설 처리 완료를 재검증 없이 자동 종료하는 기능

## 만들 수 있을까

### 필요한 기술/API

- 이미지에서 장애물 후보를 추출하는 멀티모달 모델
- 장벽 유형과 이동 프로필 영향을 연결하는 결정론적 규칙 테이블
- 시설 위치, 담당 큐, 우회 구간을 담은 검증된 데모 JSON
- 티켓 상태 전이와 전후 사진 비교를 구현하는 웹 애플리케이션
- 위치 선택용 단순 지도 또는 SVG와 모의 시설관리 보드

실제 지자체 시설관리 API의 존재, 외부 민원 시스템의 사진·위치 접수 형식, 담당 부서 자동 배정 및 제출 가능 여부는 **확인 못 함**. 따라서 하루 MVP는 외부 시스템과 통신하지 않는 모의 티켓만 생성한다.

### 하루 구현 범위

1. 세 가지 장벽 사진과 시설·우회 데모 데이터 준비: 1시간
2. 사진 분류 프롬프트와 사용자 확인 화면: 1시간 30분
3. 프로필별 영향 판정과 우회 정보 표시: 1시간 30분
4. 티켓 생성·담당 큐·상태 전이 보드: 1시간 30분
5. 재촬영 비교와 종료·재개 흐름: 1시간
6. 개인정보 가림, 실패 흐름, 발표 리허설: 30분

### 걸림돌과 대응

| 걸림돌 | 대응 |
| --- | --- |
| 그림자나 촬영 각도로 장벽을 오분류함 | 확신도와 후보 근거를 노출하고 사용자 수정, 추가 질문, 재촬영을 필수 흐름으로 둔다. |
| 사진만으로 고장 여부나 남은 통행 폭을 알 수 없음 | 보이는 사실과 추측을 분리하고 측정값을 만들어내지 않으며 `영향 확인 필요`로 판정한다. |
| 같은 장벽이 프로필마다 다르게 작용함 | 프로필별 규칙 결과를 나란히 표시하고 한 프로필의 결과를 전체 보행자에게 일반화하지 않는다. |
| 잘못된 위치나 시설 유형으로 엉뚱한 담당자에게 배정됨 | 사용자가 핀과 시설명을 확인하게 하고 불확실한 항목은 수동 분류 큐로 보낸다. |
| 시설 분류·담당 기준이나 신고 규정이 변경됨 | 규칙 버전과 적용일을 티켓에 기록하고, 실제 연동 전 관할 기관의 최신 문서를 다시 확인한다. 현재 최신 규정은 확인 못 함. |
| 재촬영 사진이 다른 장소이거나 장벽이 일부 남아 있음 | 위치·시설 식별자와 전후 화면을 함께 확인하고 자동 종료 대신 사용자 확인 또는 재개를 요구한다. |
| 사진에 얼굴·번호판 등 개인정보가 포함됨 | 업로드 전 가림 안내와 자동 가림 후보를 제공하고 데모에서는 비식별 준비 사진을 사용한다. |
| 실제 접수 API가 없거나 인증이 필요함 | MVP는 모의 티켓으로 끝내며 자동 제출 가능성을 주장하지 않는다. |

## 참고

- 기존 [휠체어·유모차 경로 에이전트](2026-09-09-휠체어-유모차-경로-에이전트.md)는 접근성 태그를 이용한 개인별 경로 추천과 장애물 발생 시 재탐색에 집중한다.
- 길막제로는 경로 엔진을 제품의 중심으로 삼지 않고, **현장에서 새로 발생한 장벽을 신고하고 담당자에게 배정하며 제거 여부를 다시 검증하는 시설관리 폐쇄 루프**에 집중한다.
- 실제 지자체 시설관리·민원 API와 자동 제출 지원 여부는 확인 못 함.
