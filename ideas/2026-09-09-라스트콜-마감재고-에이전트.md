# 라스트콜: 캠퍼스 마감재고 구조 에이전트

## 한 줄 요약
식음료 점포의 합성 POS·재고와 캠퍼스 행사·날씨 신호로 당일 잉여량을 추정하고, 안전·마진 규칙 안에서 할인 번들을 제안해 점주 승인 후 모의 게시와 재고 홀드·종료까지 수행하는 에이전트다.

## 문제
- 캠퍼스 주변 식음료 점포는 마감 전 남을 상품을 일찍 알기 어렵고, 늦은 할인은 손님에게 전달되지 않아 폐기로 이어질 수 있다.
- 점주는 영업 중 POS, 재고, 소비기한, 행사 일정, 날씨를 함께 보며 상품별 할인율과 묶음을 계산할 시간이 부족하다.
- 학생은 가까운 점포의 마감 상품을 저렴하게 살 기회를 알기 어렵지만, 무분별한 할인 알림은 피로와 과소비를 만들 수 있다.
- 현재는 감으로 생산량을 줄이거나 매장 앞에서 즉석 할인하며, 어떤 결정이 폐기와 매출에 어떤 영향을 줬는지 기록하기 어렵다.
- 소비기한, 알레르기, 보관 상태, 최소마진을 잘못 다루면 절감액보다 큰 안전·신뢰 문제가 생긴다.
- 행사와 날씨 신호가 잉여량 예측을 실제로 개선하는지와 할인 번들이 폐기를 줄이는지는 확인 못 함이다.

## 해결 방식
합성 POS·재고 흐름에서 마감 예상 잉여량을 계산하고, 소비기한·최소마진·알레르기 하드룰을 통과한 상품만 할인 번들 후보로 만든다.
점주가 수량, 가격, 게시 시간을 확인하고 승인한 경우에만 모의 게시와 재고 홀드를 실행하며, 실제 판매·결제는 하지 않는다.

### 에이전트 루프
1. 에이전트가 합성 POS 판매량, 현재 재고, 생산 시각, 소비기한, 원가, 정상가, 최소마진, 알레르기 정보를 읽는다.
2. 합성 캠퍼스 행사 일정과 날씨 신호를 읽고, 평시 판매 추세에 적용할 조정값을 만든다.
3. 마감까지 예상 판매량을 계산해 상품별 예상 잉여량과 신뢰 수준을 표시하며, 예측식과 조정값은 데모용 가정이라고 밝힌다.
4. 소비기한이 게시·수령 시간을 감당하지 못하거나, 알레르기 정보가 비어 있거나, 할인 후 최소마진을 밑도는 상품을 하드룰로 제외한다.
5. 통과 상품 중 수령 시간이 비슷하고 함께 소비하기 적절한 항목을 묶어 1인·2인 번들을 구성한다.
6. 정상가 합계, 제안 할인율, 번들가, 예상 회수매출, 학생 절감액, 예상 폐기 절감 수량을 계산 근거와 함께 보여준다.
7. 점주에게 번들 구성, 판매 수량, 가격, 게시·수령·종료 시간, 위험 표시를 제시하고 승인·수정·거절을 받는다.
8. 승인된 수량만 합성 재고에서 모의 홀드하고 데모 학생 화면에 게시한다.
9. 모의 주문이 들어오면 홀드 수량을 갱신하고, 소비기한 임박·마감·점주 중단·수량 소진 중 하나가 발생하면 게시를 종료한다.
10. 종료 후 기준 재고 대비 폐기 절감량, 정상가 대비 학생 절감액, 할인 판매 회수매출을 데모 지표로 정리한다.

### 3분 데모
- 0:00~0:30에 합성 베이커리의 POS·재고 화면에서 샌드위치 8개, 샐러드 5개, 음료 10개의 현재 상태를 보여준다.
- 0:30~1:00에 비 예보와 저녁 캠퍼스 행사 취소 신호를 반영해 예상 판매량이 낮아지고 예상 잉여량이 생기는 과정을 보여준다.
- 1:00~1:30에 소비기한 부족 상품과 알레르기 정보 누락 상품이 하드룰로 제외되는 이유를 보여준다.
- 1:30~2:00에 통과 상품으로 1인 번들 두 종류를 만들고 정상가, 번들가, 최소마진, 예상 회수매출을 비교한다.
- 2:00~2:30에 점주가 한 번들의 수량과 할인율을 수정해 승인하고 모의 게시와 재고 홀드를 실행한다.
- 2:30~3:00에 모의 주문과 수량 소진 종료를 실행한 뒤 폐기 절감량, 회수매출, 학생 절감액을 결과 카드로 보여준다.

### 지표 계산 원칙
- 폐기 절감량은 `판매하지 않았다면 폐기됐을 것으로 가정한 수량` 중 모의 판매된 수량으로 계산하며 실제 폐기 감축 효과가 아니다.
- 회수매출은 모의 판매 수량과 승인 번들가의 곱이며 결제 완료 매출이 아니다.
- 학생 절감액은 정상가 합계와 번들가의 차이이며 다른 점포 가격이나 교통비는 반영하지 않는다.
- 예측이 빗나간 경우를 숨기지 않고 예상 잉여량과 실제 합성 종료 재고의 차이를 함께 기록한다.

### 승인과 안전 원칙
- 점주 승인 없이 할인율, 판매 수량, 게시 시간, 재고 홀드를 확정하지 않는다.
- 소비기한 경과, 알레르기 정보 누락, 보관 상태 미확인, 최소마진 미달은 점주가 원해도 데모 하드룰에서 우회하지 않는다.
- 알레르기 정보는 원재료 확인을 대체하지 않으며, 실제 판매 시 점포의 최신 표시를 확인해야 한다.
- 날씨와 행사 신호는 수요 참고값일 뿐 안전 규칙이나 점주 판단보다 우선하지 않는다.
- 학생에게 구매 압박 문구를 만들지 않고 수량, 수령 시간, 알레르기, 보관 안내를 명확히 보여준다.

## 핵심 기능
### 하루 MVP
- [ ] 합성 POS·재고·소비기한·원가·알레르기 데이터를 시간에 따라 재생한다.
- [ ] 합성 행사·날씨 신호를 반영해 예상 잉여량과 계산 근거를 보여준다.
- [ ] 소비기한·최소마진·알레르기 하드룰로 부적합 상품을 제외하고 이유를 기록한다.
- [ ] 통과 상품으로 할인 번들을 만들고 가격·수량·예상 지표를 계산한다.
- [ ] 점주가 승인·수정·거절할 수 있는 승인 화면을 제공한다.
- [ ] 승인된 번들의 모의 게시, 재고 홀드, 주문, 종료 상태를 시뮬레이션한다.
- [ ] 폐기 절감량, 회수매출, 학생 절감액을 가정 기반 지표로 보여준다.

### 후속 확장
- [ ] 점포별 판매 패턴과 예측 오차를 학습해 잉여량 추정 모델을 검증한다.
- [ ] POS·재고·날씨·캠퍼스 행사 API의 제공 조건을 확인한 뒤 읽기 전용 연동부터 추가한다.
- [ ] 학생의 거리와 수령 가능 시간을 반영하되 정확한 위치 저장을 최소화한다.
- [ ] 점포가 반복 사용하는 번들 정책, 할인 상한, 알림 빈도를 설정하게 한다.
- [ ] 실제 폐기 계량과 정산 데이터를 연결해 추정 지표와 실제 효과의 차이를 검증한다.

### 제외 범위
- [ ] 실제 상품 판매, 결제, 환불, 정산을 처리하지 않는다.
- [ ] 실제 POS 재고를 차감하거나 외부 채널에 상품을 게시하지 않는다.
- [ ] 소비기한 연장, 식품 안전 판정, 알레르기 무위험 보장을 하지 않는다.
- [ ] 자동 가격 덤핑이나 점주 승인 없는 동적 가격 변경을 하지 않는다.
- [ ] 개인별 구매 이력에 기반한 과도한 타기팅과 대량 알림을 하지 않는다.

## 만들 수 있을까
### 필요한 기술/API
- 합성 판매 이벤트 생성기, 재고 상태 머신, 규칙 기반 필터, 단순 수요 추정식, 번들 조합기, 점주 승인 UI, 학생 게시 UI, 지표 대시보드가 필요하다.
- JSON 또는 로컬 데이터베이스만으로 합성 POS·재고와 모의 게시·홀드·종료의 하루 데모 구현은 가능하다고 가정한다.
- LLM은 점주용 설명과 번들 이름 초안에 사용할 수 있지만 핵심 수량·가격·안전 판정은 결정론적 규칙으로 처리한다.
- 실제 POS, 재고, 날씨, 캠퍼스 행사 API의 접근 권한, 호출 비용, 데이터 품질은 확인 못 함이다.

### 하루 안에 데모까지 갈 수 있는가
- 오전에는 합성 상품·판매·재고 스키마와 시간 재생기, 예상 잉여량 계산, 하드룰 엔진을 구현한다.
- 오후에는 번들 구성, 승인 화면, 모의 게시와 홀드·주문·종료 상태를 연결한다.
- 마감 전에는 정상 승인, 안전 규칙 제외, 점주 수정, 수량 소진 종료 시나리오를 실행하고 지표 계산을 대조한다.
- 복잡한 예측 모델 대신 이동평균과 고정 신호 가중치를 쓰는 것이 하루 MVP에 적합하다고 가정한다.

### 걸림돌과 안전장치
| 걸림돌 | 안전장치 |
| --- | --- |
| POS와 실제 재고가 다를 수 있음 | 승인 직전에 점주가 실물 수량을 확인하게 하고 불일치 시 홀드를 취소한다. |
| 소비기한이나 보관 상태가 잘못 입력될 수 있음 | 정보 누락 상품은 제외하고 점주 확인 시각과 확인자를 기록한다. |
| 알레르기 정보가 불완전할 수 있음 | 누락 상품을 제외하고 번들 화면에 원재료·교차오염 확인 필요 문구를 고정한다. |
| 과도한 할인이 손실이나 브랜드 훼손을 만들 수 있음 | 점포별 최소마진과 할인 상한을 하드룰로 두고 모든 가격 변경에 재승인을 요구한다. |
| 재고 홀드와 주문이 엇갈려 초과 판매될 수 있음 | 상태 변경을 한 경로에서 순차 처리하고 수량이 0이면 즉시 게시를 종료한다. |
| 행사·날씨 신호가 틀려 정상 판매를 방해할 수 있음 | 낮은 신뢰도를 표시하고 점주가 수량을 줄이거나 제안을 거절할 수 있게 한다. |
| 추정 폐기 절감량이 실제 성과로 오해될 수 있음 | 결과 카드에 `합성 데이터 기반 추정`을 표시하고 실제 계량값과 분리한다. |
| 마감 임박 구매가 학생의 충동 소비를 유도할 수 있음 | 과장된 긴급 문구와 반복 알림을 금지하고 수령 가능 시간과 필요 정보만 제공한다. |
| 개인정보와 구매 이력이 불필요하게 쌓일 수 있음 | 데모는 합성 사용자만 쓰고 실제 확장 시 최소 수집과 짧은 보존 기간을 기본값으로 둔다. |

## 참고
- 마감 할인 서비스와 POS 연동 사례의 실제 수수료, 운영 방식, 식품 사고 책임 범위는 확인 못 함이다.
- 캠퍼스 상권의 상품별 폐기량, 학생 가격 민감도, 적절한 알림 시간은 점주·학생 인터뷰로 확인해야 한다.
- MVP의 판매량, 날씨, 행사, 재고, 원가, 가격, 알레르기, 소비기한은 모두 합성 데이터다.
- 폐기 절감량, 회수매출, 학생 절감액은 데모 시나리오의 가정값이며 실제 효과를 주장하지 않는다.
