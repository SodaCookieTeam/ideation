# 반대심문 리허설실

## 한 줄 요약
발표자가 질의응답에서 무너지는 문제를, 성격이 다른 심사위원 에이전트 셋이 질문을 퍼붓고 사람 답변에 꼬리질문을 물어 약점 지도를 만들어 해결한다.

## 문제
- 캡스톤·공모전·학회 발표를 앞둔 학생 팀, 대학원 면접자
- 지금은 슬라이드만 다듬고 예상 질문은 "이런 거 물어볼 것 같아" 수준으로 감으로 준비한다.
- 실제로는 지표 근거, 확장성, 차별점 질문에서 막힌다. 어느 슬라이드가 약한지 사전에 모른다.

## 해결 방식
1. **자료 독해관** — 슬라이드와 발표문에서 주장과 근거를 추출하고, 근거 없는 주장에 표시를 붙인다
2. **심사위원 3인 페르소나** — 기술 깐깐형 / 사업성형 / 사용자 관점형이 각자 질문을 생성한다
3. **압박관** — 사람이 낸 답변을 받아 꼬리질문을 만든다
4. **약점 집계관** — 막힌 질문을 모아 보강할 슬라이드 항목을 제안한다

사람이 답변을 타이핑하면 그 자리에서 꼬리질문이 붙는다.

### 왜 역할을 나누는가
한 번 호출로 "예상 질문 10개"를 받으면 관점이 한 톤으로 쏠리고 꼬리질문이 없어 실전 압박이 재현되지 않는다. 페르소나 분리가 질문의 축을 벌리고, 사람 답변이 다음 질문의 입력이 되는 루프가 있어야 약점이 드러난다.

## 핵심 기능
- [ ] 발표 자료에서 근거 없는 주장 자동 표시 (최소 기능)
- [ ] 3개 관점 질문 생성과 사람 답변에 대한 실시간 꼬리질문
- [ ] 막힌 질문 기준 보강 항목 리스트
- [ ] 슬라이드별 위험 등급 표시

## 만들 수 있을까
- 필요한 기술: LLM, PDF·마크다운 텍스트 추출, 스트리밍 응답, 세션 로그 저장
- 하루 안에 데모까지: **가능.** 질문 3개는 병렬 호출 한 홉이고 꼬리질문도 한 홉이라 대기가 짧다. 자료 입력을 텍스트와 마크다운으로 한정해 파싱 리스크를 뺀다.
- 걸림돌
  - 페르소나 셋이 비슷한 질문을 내면 구조의 의미가 사라진다. 프롬프트에서 질문 축을 강제로 나눈다.
  - 사람이 타이핑하는 시간이 있어 발표 시연 흐름 설계가 필요하다.
  - 슬라이드 이미지 안의 텍스트는 못 읽는다.

## 시연 장면
우리 팀 발표 슬라이드를 그대로 넣는다. 세 심사위원 아바타가 각각 다른 색 말풍선으로 질문을 띄운다. 발표자가 한 질문에 답을 입력하면 깐깐형이 즉시 "그 수치의 측정 방법은?"이라고 꼬리를 문다. 발표자가 "기각"을 누른 질문은 약점 목록으로 넘어가고, 오른쪽 패널에 보강할 슬라이드 3줄이 쌓인다.

## 참고
- 발표 코칭 도구는 대개 원고를 다듬어 준다. 이 아이디어는 사람을 피고석에 세우고 답변을 입력값으로 받는 압박 루프이며, 산출물이 원고가 아니라 **약점 지도**다.
- 주제 적합성이 넓다. 발표·설득·검증이 걸린 어떤 주제로도 변형이 가능하고, 본선 당일 우리 팀 발표 준비에도 그대로 쓸 수 있다.
