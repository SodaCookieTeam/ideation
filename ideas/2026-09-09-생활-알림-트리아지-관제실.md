# 생활 알림 트리아지 관제실 (5-에이전트 대립 구조)

## 한 줄 요약
하루에 쏟아지는 문자와 고지서를 다 안 읽고 넘기면서 "혹시 중요한 걸 놓쳤나" 불안해하는 사람에게, 5개 에이전트가 대립해서 **"오늘 해야 할 2개"와 "무시해도 되는 나머지"를 근거와 함께 갈라주는** 서비스.

## 문제

### 누가 겪는 문제인가
- 문자와 우편, 앱 알림을 하루에 수십 건 받는 모든 사람
- 특히 자기 이름으로 고지서와 행정 안내가 오기 시작한 사회초년생과 1인가구

### 지금은 어떻게 버티고 있는가
- 대부분을 읽지 않고 넘긴다. 실제로 이게 가장 흔한 대처다.
- 중요해 보이는 것만 캡처해두고 나중에 다시 찾는다.
- 연체 문자나 과태료 고지가 오고 나서야 놓친 것을 안다.

### 왜 불편한가
- **진짜와 사칭이 섞여 온다.** 안랩의 2025년 4분기 피싱 문자 분석에서는 피싱 문자의 절반가량이 금융기관을 사칭한 것으로 나타났다. 정부도 지원금 지급 시기에 맞춰 스미싱 경고를 냈다.
- 그래서 사람들은 **전부 무시하는 쪽으로 학습된다.** 그 결과 진짜 납부 기한과 신청 마감도 같이 묻힌다.
- 놓쳤을 때의 손해가 비대칭이다. 광고 하나를 무시하면 손해가 0인데, 납부 기한 하나를 무시하면 가산금이 붙는다.
- 남는 건 "안 읽은 것 중에 큰일이 있었을까" 하는 상시 불안이다. 이 불안 자체가 매일 반복되는 비용이다.

### 기존 도구가 못 푸는 지점
스팸 차단은 **가짜를 걸러줄 뿐, 진짜 중에서 무엇이 급한지는 말해주지 않는다.**

그리고 LLM 하나에 "이 문자들 중요한 것 골라줘"를 시키면 거의 전부 "확인이 필요합니다"로 돌아온다. 모델은 틀렸을 때 책임을 피하려고 전부 노란불을 켠다. 전부 노란불이면 사용자는 전과 똑같이 다 무시하게 되고, 도구는 쓸모가 없어진다.

**필요한 건 "무시해도 된다"를 근거를 걸고 말해주는 구조다.** 그래서 역할을 나눠 대립시킨다.

## 해결 방식

사용자는 문자 뭉치를 붙여넣거나 고지서 사진을 올린다. 뒤에서는 5개 에이전트가 순서대로 붙고, 마지막에 세 칸으로 갈라진 관제 화면이 나온다.

```
   문자 붙여넣기 / 고지서 사진
              │
              ▼
   ① 판독관  발신자·종류·핵심 필드 추출, 원문 근거 보존
              │
      ┌───────┴───────┐
      ▼               ▼
   ② 사칭 검증관    ③ 기한·금액 계산관
   (가짜면 즉시 격리)  (D-day·가산금을 코드로 계산 = 시급 근거)
                        │
                        ▼
                   ④ 미룸 변호인
                   ("근거 없다, 무시해도 된다" 반박)
                        │
                        ▼
                   ⑤ 행동 카드 작성관
                   (살아남은 건에 대해 할 일과 보낼 문안)
                        │
                        ▼
        빨강 지금 할 일 / 노랑 확인 필요 / 회색 무시해도 됩니다
```

1. **① 판독관** — 붙여넣은 텍스트와 사진을 공통 스키마로 정규화한다. 발신 주장, 문서 종류, 날짜, 금액, 링크를 뽑고 각 값의 **원문 근거 문장을 함께 남긴다.**
2. **② 사칭 검증관** — 링크 도메인, 발신번호 형태, 문구 패턴, "공식 채널이 이런 요구를 하는가"를 따져 사칭을 격리한다. 사칭으로 판정되면 아래 단계로 넘기지 않고 빨강 경고로 뺀다.
3. **③ 기한·금액 계산관** — 남은 건의 D-day와 놓쳤을 때 손해액을 **코드로 계산한다.** LLM 이 더한 숫자는 발표에서 신뢰를 잃기 때문에 산술은 전부 코드로 돌린다. 이 에이전트가 내놓는 숫자가 곧 "시급하다"의 근거다.
4. **④ 미룸 변호인** — 계산관이 낸 근거를 공격한다. 기한이 없거나 금액이 0이거나 행동이 필요 없는 건을 "무시해도 됩니다"로 끌어내린다. **근거를 못 내면 미룸 변호인이 이긴다.** 이 승패 규칙이 전부 노란불이 되는 것을 막는다.
5. **⑤ 행동 카드 작성관** — 빨강과 노랑으로 남은 건만 받아 지금 할 일 한 줄, 필요하면 보낼 문안이나 전화 스크립트를 만든다.

오케스트레이터는 에이전트가 아니라 코드다. 위 순서를 고정 파이프라인으로 돌리고 결과를 합친다. 조율을 LLM 에 맡기면 하루 안에 안 끝난다.

### 왜 역할을 나누는가
핵심은 ③과 ④의 **대립**이다.

한쪽은 숫자로 "급하다"를 증명해야 하고, 다른 쪽은 "근거 없다"를 주장한다. 판정은 이 대결의 결과로 정해지고, 근거가 없으면 회색으로 떨어진다. 이렇게 해야 화면에 **회색이 실제로 생긴다.** 회색이 생기는 순간 이 도구는 사용자의 시간을 실제로 줄여준다.

## 핵심 기능
- [ ] 문자 뭉치 붙여넣기와 고지서 사진 업로드 → 건별 카드로 구조화 (최소 기능)
- [ ] 사칭 의심 건 격리 및 판정 근거 표시 (최소 기능)
- [ ] 기한·손해액 코드 계산과 D-day 표시 (최소 기능)
- [ ] 시급 근거 대 미룸 반박의 대립 뷰, 3색 등급 확정 (최소 기능)
- [ ] 빨강·노랑 건에 대한 행동 카드와 문안 생성 (최소 기능)
- [ ] **미룸 변호인 끄기 토글** — 껐을 때 전부 노란불로 돌아가는 것을 보여주는 시연 장치
- [ ] (있으면 좋음) `.ics` 내보내기, 처리 완료 체크, 판정 근거 접기·펴기

## 5명 역할 분담 (에이전트 = 1인 1담당)

| 담당 | 맡는 것 | 주 작업 | 붙는 지점 |
| --- | --- | --- | --- |
| A | 오케스트레이터 + 프론트 | 파이프라인 코드, 관제 3칸 UI, 토글 | 모든 에이전트의 입출력 스키마 |
| B | ① 판독관 | 텍스트·이미지 파싱, 정규화 스키마, 원문 근거 보존 | ②③에 건 목록 전달 |
| C | ② 사칭 검증관 | 판정 규칙과 프롬프트, 격리 뷰 | ① 결과 입력 |
| D | ③ 기한·금액 계산관 | 날짜·가산금 계산 코드, 시급 근거 생성 | ① 결과 입력, ④로 전달 |
| E | ④ 미룸 변호인 + ⑤ 행동 카드 | 반박 로직, 등급 확정 규칙, 문안 생성 | ③ 결과 입력 |

병렬 개발의 조건은 하나다. **시작할 때 건(item) 스키마와 판정(verdict) 스키마를 먼저 못 박는 것.** 스키마만 고정하면 각자 mock 데이터로 독립 개발하다 마지막에 붙인다. B 의 파서가 안 끝나도 C·D·E 는 샘플 JSON 으로 계속 갈 수 있다.

## 만들 수 있을까

- 필요한 기술
  - LLM 구조화 출력(JSON 스키마 강제) — 판독, 사칭 판정, 반박, 문안 생성
  - 멀티모달 LLM 또는 OCR — 고지서 사진. 사진이 막히면 텍스트 입력만으로도 데모가 성립한다.
  - 날짜·금액 계산은 일반 코드로 처리
  - 웹 프론트, 세션 범위 저장
- 하루 안에 데모까지 갈 수 있는가
  - **가능하다고 본다.** 외부 연동이 0이고 입력이 붙여넣기라 인증 절차가 없다. 이 레포의 [주제 100선](../research/주제-100선.md)에서 정리한 "연동이 걸리면 하루 데모가 무너진다" 규칙을 처음부터 피해 설계했다.
  - 다만 에이전트가 5개라 조율 시간이 붙는다. 100선의 지적대로 **구조로 승부할 주제는 아침에 바로 결정해야 한다.** 점심 넘겨서 고를 주제가 아니다.
- 걸림돌
  - **사칭 판정을 틀리면 피해가 크다.** 진짜를 가짜로 몰면 사용자가 납부를 놓친다. 그래서 "차단"이 아니라 "의심, 공식 앱에서 직접 확인"으로 표현을 못 박고, 최종 판단은 사용자에게 남긴다.
  - **회색 판정의 책임 문제.** "무시해도 됩니다"가 틀릴 수 있다. 회색 카드에도 근거를 항상 붙이고, 되돌려 볼 수 있게 남긴다. 화면에 "정보 제공이며 최종 확인은 사용자 몫" 고정 문구를 둔다.
  - 통신사·기관별 문자 포맷이 제각각이라 파싱 실패가 나온다. 데모용 샘플 세트를 미리 만들어 둔다.
  - 가산금·연체료의 실제 요율은 기관마다 다르다. **확인 못 함.** 데모는 요율을 화면에 명시하고 계산 과정을 펼쳐 보이는 방식으로 간다.
  - 개인정보가 그대로 들어온다. 세션 범위로만 두고 기본 저장하지 않는다.

## 시연 장면

실제 문자 12건을 통째로 붙여넣는다. 카드가 우르르 쌓이고 처음엔 **전부 노란불**이다.

그다음 에이전트들이 순서대로 붙는다. 사칭 검증관이 "정부지원금 신청" 문자 1건을 링크 도메인 불일치로 집어 **빨강으로 격리**한다. 계산관이 관리비 고지서 1건을 **D-1, 미납 시 가산금**으로 계산해 빨강으로 올린다. 그리고 미룸 변호인이 나머지 10건 중 9건을 "기한 없음, 금액 없음, 행동 불필요"로 **회색으로 끌어내린다.**

상단 숫자가 `12건`에서 **`오늘 할 일 2건`**으로 바뀐다.

여기서 토글을 누른다. **미룸 변호인을 끈다.** 회색 9건이 전부 노란불로 되돌아오며 화면이 다시 지저분해진다. 이 한 번의 토글이 "왜 에이전트를 나눴는가"를 말보다 빠르게 증명한다.
