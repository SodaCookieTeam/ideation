# shortlist 선별 기록

12개 분야에 발상 에이전트를 병렬로 띄워 각 10건씩 **120건**을 받고, 그중 **10건**을 `ideas/`에 문서로 올린 과정을 남긴다.

- 문서로 쓰지 않은 나머지 108건은 [아이디어 보관함](아이디어-보관함.md)에 있다.
- 이 기록의 목적은 순위가 아니라 **판단의 근거**다. 주제가 나와서 순위를 다시 짤 때 "왜 그때 이렇게 봤는지"를 알 수 있어야 한다.

작성: 2026-09-09

## 선별 기준

[README](../README.md)의 4개 기준을 적용했다. 주제가 아직 공개되지 않았으므로 1번은 "주제 변형 여지"로 대체했다.

1. **하루 안에 데모가 나오는가** — 통과 조건. `가능` 판정만 후보로 올렸다.
2. **문제가 분명한가** — "누가 왜 쓰는지"를 한 문장으로 말할 수 있는가.
3. **보여줄 게 있는가** — 발표에서 시연할 30초 장면이 그려지는가.
4. **차별점이 있는가** — 대기업이 이미 하는 것과 각도가 다른가.
5. **서로 겹치지 않는가** — 10건이 한 계열에 쏠리지 않게 흩었다.

`애매` 판정은 전부 떨어뜨렸다. 하루짜리 대회에서 "애매"는 발표 시간에 데모가 안 되는 쪽으로 기운다.

## 알아야 할 편향

**개발자 계열이 3건**이다(레드팀, 스크린리더, 디버깅 튜터). 심사위원이 개발자일 가능성과 데모 데이터를 바로 구할 수 있다는 이점을 노린 의도적 배치다.

**주제가 사회문제 계열로 나오면 이 3건은 후순위**다. 그 경우 재난문자, 키오스크, 분리배출이 앞으로 온다.

## 관찰

### 연동이 걸린 아이디어는 예외 없이 무너진다

오픈뱅킹, 마이데이터, 학사 시스템 로그인, 배달·중고 플랫폼 API, 전화망 발신이 필요한 것은 **전부** `애매` 이하로 떨어졌다. 반대로 사용자가 직접 넣는 입력(사진, 붙여넣기, 파일 업로드)으로 우회한 것들이 살아남았다.

본선 당일에도 이 규칙을 판단 기준으로 쓰면 된다. **"이거 로그인이나 API 연동 필요한가?"** 한 마디로 후보를 반으로 줄일 수 있다.

수요 신호가 강하다는 뜻이지만, 그만큼 흔한 발상이라 차별점을 확실히 세워야 한다. 계약서 계열을 6번 중 하나가 아니라 **대립 구조**로 올린 이유가 이것이다.

### 팀원 아이디어와의 중복

`main`에 이미 올라온 팀원 아이디어와 겹치는 것을 정리했다.

| 팀원 아이디어 | 겹치는 내 후보 | 처리 |
| --- | --- | --- |
| 무료체험 종료 지킴이 | 유령 구독 사냥꾼 | 접음. 사후 회수 각도만 메모로 남김 |
| 휠체어·유모차 경로 에이전트 | 갈 수 있나 리포트 (보관함) | 보관함에 겹침 메모 표시 |
| 멀티 에이전트 지원금·복지 비서 | 없음 | 기존 지원금 헌터의 멀티에이전트 확장이라 별개 |

그 뒤로도 팀원이 아이디어를 계속 올려 지금 `ideas/`에는 팀원 문서가 9건 더 있다(지각 방지, 옷장 활용률 분석기, 외국인 정착 행정 순서, 층간소음 갈등 중재, 공공시설 방문, 근처에 온 김에 등). **이 9건은 shortlist 10건과 겹치지 않는다**는 것을 확인했다.

발상 에이전트에게는 당시 있던 기존 아이디어 4건만 중복 금지 목록으로 줬다. 목록이 이렇게 빨리 늘어나므로, **다음에 발상을 돌릴 때는 `ideas/` 전체를 중복 금지 목록에 넣어야 한다.** 그러지 않으면 이번처럼 겹치는 후보를 만들고 나서 걷어내게 된다.
