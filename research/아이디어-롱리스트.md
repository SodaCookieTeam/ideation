# 아이디어 롱리스트 (120건)

12개 분야에 발상 에이전트를 병렬로 띄워 각 10건씩 받은 원재료 목록이다. 이 중 10건을 `shortlist`로 올렸고, 나머지는 **주제가 나오면 꺼내 쓸 재료**로 여기 남긴다.

목록의 용도는 하나다. 본선 오전에 주제가 공개되면 이 표를 훑어 **주제에 가장 가까운 줄을 찾는 것.** 그러니 지우지 않는다.

작성: 2026-09-09 · 하루 데모 판정은 발상 단계의 자체 평가이며 실측이 아니다.

## 선별 기준

[README](../README.md)의 기준을 그대로 적용했다. 주제가 아직 없으므로 1번은 "주제 변형 여지"로 대체했다.

1. **하루 안에 데모가 나오는가** — 통과 조건. `가능` 판정만 최종 후보로 올렸다.
2. **문제가 분명한가** — "누가 왜 쓰는지"를 한 문장으로 말할 수 있는가.
3. **보여줄 게 있는가** — 발표에서 시연할 30초 장면이 그려지는가.
4. **차별점이 있는가** — 대기업이 이미 하는 것과 각도가 다른가.
5. **서로 겹치지 않는가** — 10건이 한 계열에 쏠리지 않게 흩었다.

`애매` 판정은 전부 떨어뜨렸다. 하루짜리 대회에서 "애매"는 발표 시간에 데모가 안 되는 쪽으로 기운다.

주의할 편향이 하나 있다. 개발자 계열이 3건(레드팀, 스크린리더, 디버깅 튜터)이다. 심사위원이 개발자일 가능성과 데모 데이터를 바로 구할 수 있다는 이점을 노린 의도적 배치이지만, **주제가 사회문제 계열로 나오면 이 3건은 후순위**다. 그 경우 재난문자·키오스크·분리배출이 앞으로 온다.

## 아까웠던 탈락 후보

`가능` 판정이었는데 계열 중복이나 시각 효과 때문에 밀린 것들이다. 주제에 따라 바로 승격할 수 있다.

| 아이디어 | 밀린 이유 |
| --- | --- |
| 보내기 전 이메일 역풍 시뮬레이터 | 반대심문 리허설실과 "페르소나 반응 예측" 계열이 겹침 |
| 사기 대화 판독기 | 접근성 계열의 고령자 스미싱 판정기와 겹침. "다음에 올 말 예측"은 아까움 |
| 캠퍼스 분실물 사진 매칭 | 심사위원 텀블러를 미리 등록해 두는 데모 트릭이 훌륭. 데이터 시드 확보가 변수 |
| 골목 가게 메뉴판 리뉴얼 | QR 스캔 관객 참여형. 주최 성격(캠퍼스타운)과 잘 맞음 |
| 우편물 브리핑 (음성 한 통) | 화면을 검게 두고 음성만 흘리는 연출이 인상적. 시각 효과가 약해 밀림 |
| 강의실 실시간 질문 클러스터링 | 심사위원 폰 참여형으로 임팩트 최상. `애매` 판정(현장 네트워크 의존)이라 제외 |

## 관찰

같은 아이디어가 여러 분야에서 독립적으로 나온 경우를 세어 봤다. 겹침 횟수가 곧 문제의 절실함이다.

| 발상 | 몇 개 분야에서 나왔나 |
| --- | --- |
| 계약서 독소조항 스캐너 | 6 (공공, 금융, 접근성, 캠퍼스, 채용, 에이전트구조) |
| 발표·면접 꼬리질문 코치 | 4 (교육, 콘텐츠, 채용, 에이전트구조) |
| 강의계획서 → 학기 부하 | 2 (교육, 캠퍼스) |
| 재난문자 → 개인 행동 지시 | 2 (공공, 환경) |
| 팀플 기여도 정리 | 2 (교육, 캠퍼스) |

또 하나. 12개 분야 중 **"연동이 필요한 아이디어는 예외 없이 하루 데모가 무너진다."** 오픈뱅킹, 마이데이터, 학사 시스템 로그인, 배달·중고 플랫폼 API, 전화망 발신이 걸린 것은 전부 `애매` 이하로 떨어졌다. 반대로 **사용자가 직접 넣는 입력(사진, 붙여넣기, 파일 업로드)** 으로 우회한 것들이 살아남았다. 본선 당일에도 이 규칙을 기준으로 쓰면 된다.
